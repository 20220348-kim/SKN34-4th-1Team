# GovBiz Mobile

## 리포트 앱 알림

`메뉴 → 알림 설정`에서 이메일과 별도로 이 기기의 리포트 앱 알림을 켜고 끕니다.
권한 요청은 켜기를 누를 때만 실행하며, 알림 선택은 로그인 후 해당 ID의 본인 리포트를 열고 AI를 재호출하지 않습니다.
처음 권한을 요청하기 전과 거부 상태를 구분합니다. 거부 상태는 `기기 설정 열기`로 이동하고 복귀하면 권한을 다시 읽으며 수신을 자동으로 켜지 않습니다.
기기 수신과 마감 알림·이메일·앱 알림 채널은 네이티브 스위치로 조작합니다. 저장 중에는 잠그고 실패하면 서버에서 확인한 기존 상태를 유지합니다.
같은 화면 위쪽에서 웹 프로필과 같은 [관심 공고 마감 알림](../../docs/deadline-reminders.md)(알림 시점·이메일·앱 알림)을 저장합니다.
마감 알림을 누르면 공고 식별자로 공고 상세를 엽니다.
Expo 프로젝트·Android FCM 인증과 개발용 앱 빌드가 필요합니다. Firebase DB/Auth는 사용하지 않습니다.
[서버·앱 설정과 Android 에뮬레이터 확인 절차](../../docs/mobile-report-push.md)를 참고하세요.

기존 웹과 같은 계정·API·데이터를 사용하는 Expo React Native iOS·Android 앱입니다.
웹은 `frontend/web/`, 공통 TypeScript 업무 계약·응답 검증은 `frontend/packages/shared/`에서 관리합니다.

## 관리자 Gov 에이전트

서버에서 확인한 로그인 계정의 역할이 `ADMIN`이면 검색의 AI 모드를 `Gov 에이전트`로 표시합니다.
일반 회원과 비로그인은 기존 AI 대화 검색을 사용합니다. 관리자 ID·이메일은 하드코딩하지 않습니다.
`ChatScreen → shared GovAgent API → 모바일 Bearer fetch → Core AdminPrincipal → 기존 GovAgentService`로 요청하고,
검색 조건 제안은 사용자가 확인한 뒤 기존 검색 API로 실행합니다.

선택 공고 막대에는 `원문 질문 · 신청서 쓰기 · 중복 검토` 세 기능을 표시합니다. 원문 질문은 같은 입력창과
대화 아래 기본 질문 칩을 사용하며, 이미 물은 질문은 제외하고 근거 원문은 접어서 표시합니다. 신청·검토 버튼은
Core의 경로 선택이나 AI를 호출하지 않고 대화 업무 카드를 만듭니다.
신청 카드는 기존 `ApplicationPreparationNewScreen`의 인라인 표시로 양식·작업 조회와 입력칸 분석을 수행합니다.
양식 선택·작성·문서 생성은 기존 신청 문서 화면에서 이어갑니다. 중복 검토 카드는 기존
`CombinationReviewEditorScreen → useCombinationReview`로 공고 두 개·제목·내 상황을 저장하고 명시적으로 검토를 실행합니다.
실행 후에는 기존 검토 결과 화면으로 이동합니다. 기존 미확인 요청 보관·동일 요청 키·오류 경계를 유지합니다.

카드를 접으면 입력을 보존하고 조회·폴링을 멈춥니다. 최신 업무 카드만 활성화하며 신청 카드는 선택 공고도 일치해야 합니다.
선택 공고와 Gov 답변, 저장한 검토 ID는 기존 schemaVersion 1 대화 기록에 보관합니다. 기록 열기만으로 AI를 호출하지 않으며,
일반 회원에게 Gov 업무 실행 패널을 표시하지 않습니다. 새 검색·새 대화는 선택을 해제하고 계정·권한 변경과 취소 뒤 응답은 폐기합니다.
파트너 요청의 역할·지역·분야·공고 조건을 대화 기록에 보존하고 기존 Core 추천 GET API로 모집글 세 건을 조회합니다.
추천 응답은 shared DTO로 검증·변환하며 모집글 상세와 전체 목록은 기존 앱 협업 화면으로 연결합니다.
추천 조회 실패를 빈 목록으로 대체하지 않으며 기록 복원만으로 추천이나 AI를 자동 호출하지 않습니다.
인증·권한 오류와 시간 초과는 명시적으로 표시하며 일반 검색으로 자동 대체하지 않습니다.

## 로그인 회원의 GovBiz 도우미

로그인 상태가 확인된 계정에서 이동형 말풍선 버튼과 `메뉴 → 서비스 안내 → GovBiz 도우미`를 제공합니다.
짧게 누르면 전체 화면 도우미를 열고, 길게 누른 뒤 끌어서 옮기면 가까운 좌우 가장자리에 붙습니다.
안전 영역과 하단 입력·실행 영역을 피해 높이를 제한하며 키보드·기존 시트·인증 화면·앱 백그라운드에서는 버튼을 숨깁니다.
스크린리더의 열기·좌우·위아래 이동 동작도 제공합니다. 실제 기기의 터치·안전 영역 확인은 별도입니다.
도우미 Modal 안의 별도 `SafeAreaProvider`가 해당 창의 안전 영역을 측정해 하단 여백을 갱신합니다.
시스템이 이미 제외한 하단 영역을 중복해서 확보하지 않으며 측정된 안전 영역에 4px의 여유만 추가합니다. 키보드가 열리면 하단 여백은 제거합니다.

버튼 위치만 기존 SecureStore에 API·계정별로 저장합니다. 저장·복원 실패는 안내하고 현재 앱의 위치는 유지합니다.
대화와 작성 중 질문은 로그인 세션의 메모리에만 보관합니다. 화면 이동·닫기 후에는 이어서 보며 로그아웃·세션 만료·계정 전환·같은 계정 재로그인·앱 재시작 시 초기화합니다.
닫기·중지·백그라운드 전환은 답변 대기를 취소하고 늦은 응답을 폐기합니다. 서버에서 이미 시작한 실행·비용 취소는 보장하지 않습니다.

주제별 질문은 모바일 도움말로 답하고 AI를 호출하지 않습니다. 자유 질문은 `EXPO_PUBLIC_ASSISTANT_AI_ENABLED=true`로 빌드한 경우에만 표시합니다(기본 꺼짐).
열었던 페이지 이름과 해당 화면의 주요 질문 2~3개를 먼저 표시합니다. 검색·관심함·리포트·공고 상세·알림·계정·기업 정보·협업·요금제와
신청문서의 선택/답변/검토/결과/온라인 입력 화면을 구분합니다. `다른 주제 보기`에서 전체 주제와 추가 질문을 선택할 수 있습니다.
입력만 할 때는 추천을 유지하고 질문 전송·추천 질문 선택으로 대화를 시작하면 추천 질문과 주제 선택 영역을 숨깁니다.
답변 완료·입력 삭제·같은 화면에서 닫기 후 재진입은 추천 표시 상태를 유지합니다. `새 대화` 또는 다른 화면·다른 공고에서 열 때 추천을 다시 표시합니다.
재진입은 기존 대화와 미전송 입력을 유지합니다.
다른 페이지에서 다시 열면 추천 질문만 그 페이지에 맞춰 갱신하고 같은 로그인 세션의 대화는 유지합니다.
공고 상세의 준비된 원문 질문 안내는 같은 복합 공고 ID로 질문 창만 엽니다. 이미 작성한 질문을 보존하며 AI를 자동 호출하지 않습니다.
`AssistantProvider → shared AskAssistantUseCase → mobile api/assistant → Bearer POST /api/v1/assistant/messages → 기존 Core·AI Service`를 사용하며,
응답은 shared DTO로 검증·변환합니다. AI 장애·401·429·시간 초과를 정상 도움말 답으로 바꾸지 않고 오류와 수동 재시도를 제공합니다.

서버가 내려준 `/app` 경로는 허용된 네이티브 경로로만 변환하고 카드 종류·복합 공고 ID와 목적지가 일치해야 합니다.
검색어와 선택 공고 질문은 URL 대신 해당 로그인 세션의 메모리로 전달합니다. 기존 입력 교체는 확인을 받고 입력만 채우며 AI를 자동 실행하지 않습니다.
신청문서는 선택 공고가 있을 때 기존 새 신청 화면에 연결하며 양식 분석·초안 생성은 기존 화면의 명시적 요청을 유지합니다.
서버 HTTP·DB 계약, 웹 도우미와 비로그인 지원사업 AI 검색은 변경하지 않습니다.

## 첫 실행과 비로그인 이용

첫 실행은 세션·기기 소개 기록을 확인한 뒤 기능 소개 4장의 현재 진행 바를 5초 동안 서서히 채우고 다음 장으로 넘깁니다. 이전 칸은 채워지고 이후 칸은 비어 있습니다. 마지막 장도 5초 동안 채운 뒤 멈추며,
수동 이동은 가로 스와이프만 제공합니다. 건너뛰기·이전·다음 버튼과 진행 표시 선택은 없고 진행 표시로 현재 위치와 다음 장으로 넘어가기까지의 시간을 안내합니다. `회원가입하고 시작하기`는
기존 이메일 회원가입으로, 가로로 배치한 `이미 계정이 있습니다`는 R05 로그인 방법 시트로,
`로그인 없이 둘러보기`는 공개 검색으로 연결합니다. 가입·로그인 시트를 닫으면 소개를 유지하며,
둘러보기 선택 또는 확인된 로그인 뒤 완료 기록을 기존 SecureStore의 `govbiz.introduction.v1`에 기기 단위로 저장합니다.
저장·조회 실패는 명시적으로 안내합니다. 기존 로그인 계정과 소개를 마친 비로그인 사용자는 기존 화면으로 진입하고,
세션 복원 실패는 비로그인으로 간주하지 않습니다. 사용자가 공개 공고 둘러보기를 선택해도 저장된 세션을 지우지 않습니다.
소개 속 카드는 실제 검색의 조건·결과 카드 모양을 재사용한 기능 설명용 예시이며 실제 검색·개인 데이터가 아닙니다.
R05 로그인 방법 시트와 인증 폼은 실제 이메일·카카오·Google 인증으로 연결합니다.
두 화면의 소셜 버튼은 기존 활성화 설정·네이티브 빌드 조건과 서버의 `GET /api/v1/auth/oauth/providers`를 모두 확인한 공급자만 제공합니다.
조회 중에는 확인 상태를 표시하고, 조회 실패에는 오류·수동 재시도를 제공하며 이메일 로그인은 유지합니다. 소셜 설정을 임의로 활성화하지 않습니다.
소셜 인증 중에는 중복 실행·다른 인증 방법 진입·시트 닫기·기기 뒤로가기를 잠급니다. 브라우저 인증 취소는 로그인 방법 시트를 유지하며,
확인된 로그인 세션을 받은 뒤에만 보던 화면의 선택한 작업을 한 번 이어갑니다.
이메일 인증 폼은 이메일·비밀번호·로그인 버튼 아래에 소셜 버튼을 두고 회원가입·비밀번호 찾기는 한 가로줄에 배치합니다.
카카오는 노란 바탕·검은 말풍선, Google은 흰 바탕·회색 테두리·표준 G 로고를 두 화면에서 같은 크기로 사용합니다.

소개를 다시 확인하려면 로그인 여부와 관계없이 `메뉴 → 기능 소개 다시 보기`를 누릅니다.
배포 앱에서도 소개 모달을 열며 완료 기록과 로그인 세션을 유지하고 앱을 다시 로드하지 않습니다.
다시보기에서는 가입·로그인 버튼 대신 닫기와 메뉴 복귀를 제공합니다. 닫기·Android 뒤로 가기는 기존 메뉴로 돌아가고, 다시 열면 첫 장부터 시작합니다.

비로그인은 AI 검색·필터 목록·공고 상세·공식 원문·협업 모집글·요금제를 조회할 수 있습니다. AI 추천은 서버가 공개한
최대 2건과 추가 결과 수를 표시하며 필터 목록에는 이 제한을 적용하지 않습니다. 관심함·리포트·메뉴의
개인 기능은 로그인 후 이용합니다. 비로그인 하단은 검색·협업·요금제·메뉴 4탭이며,
메뉴에는 모든 기능을 표시하고 개인 기능에 `로그인 후 이용`을 안내합니다. 상단 오른쪽은 비로그인일 때 기존 로그인 폼 진입, 로그인일 때 로그아웃을 제공합니다.
로그아웃은 기존 기기 세션·서버 세션·앱 알림 연결 종료를 사용하며 처리 중 중복 실행을 막고 일부 종료 실패도 메뉴에서 안내합니다. 개인 기능 선택은 로그인 안내를 먼저 열고,
취소하면 메뉴를 유지하며 확인된 로그인 후에만 선택한 기능으로 이동합니다. 로그인 후 하단은 기존 검색·관심함·리포트·메뉴 4탭입니다.
비로그인의 `내 프로필`에서 로그인하거나 직접 열린 계정 화면에서 인증하면 메인 검색 화면으로 이동합니다.
공고 저장·결과 복원 등 선택한 작업이 있는 로그인은 해당 작업을 이어갑니다.
협업 탭에서 로그인하면 선택한 모집글·제안함 진입 조건을 유지해 기존 메뉴 안의 협업 화면으로 이동합니다.
하단 `메뉴`를 누르면 마지막 하위 화면 대신 메뉴로 돌아갑니다. 하위 주소로 직접 진입해도 메뉴를 돌아갈 화면으로 두며,
신청문서의 미저장 답변은 기존 저장·이탈 방지를 거쳐 복귀합니다. 저장 실패 시 답변과 작성 화면을 유지합니다.

`LoginFlowProvider`는 보던 화면 위에서 안내·로그인 방법 시트·기존 이메일 인증 폼을 엽니다. 취소는 화면을
이동하거나 검색 조건·결과를 지우지 않습니다. 인증 요청 중에는 중복 취소·제출을 막고, 성공 뒤 선택한 작업만
이어갑니다. 공고 저장은 저장 상태를 먼저 확인해 이미 담은 공고를 해제하지 않고, 원문 질문은 입력 화면만 열어
명시적인 전송 전에는 AI를 호출하지 않습니다. 회원 유형·기업 등록 온보딩은 포함하지 않으며,
AI 검색 외 로그인 후 화면은 기존 구현을 유지합니다.

검색 결과 복원은 `ChatScreen → shared RestoreSupportProgramSearchUseCase → mobile api/searchResults →
shared 공고 HTTP 클라이언트 → POST /api/v1/support-programs/search/results`이며 검증된 Bearer 세션을 사용합니다.
DTO를 내부 검색 모델로 변환하는 위치는 모바일 API 경계이며 shared의 `toSupportProgram` Mapper를 재사용합니다.
복원은 해석·유료 검색을 다시 실행하지 않습니다. 취소·계정 변경·새 대화 이후의 이전 응답은 폐기하고,
410 만료와 조회 실패를 구분합니다. 만료 뒤 재검색도 조건을 확인한 사용자의 전송으로만 실행합니다.

## 인증과 계정 관리

`내 프로필`은 기존 Core API의 비밀번호 변경과 계정 삭제 미리보기·삭제를 Bearer로 연결합니다.
삭제는 미리보기 확인 → 삭제 의사·현재 비밀번호 확인(비밀번호 없는 소셜 계정은 생략) → 서버 성공 → 기기 세션 정리 순서입니다.
다른 계정으로 전환한 뒤 도착한 이전 응답은 적용하지 않습니다. 비밀번호 찾기는 인증번호 발송·확인·새 비밀번호 저장 API를 사용하고 로그인 화면으로 복귀합니다.
재설정 메일은 서버의 발송 설정이 필요하며, 미가입·소셜 전용 계정·메일 발송 불가·인증 만료는 각각 오류로 안내합니다.

## 정책·도움말·문의 안내

현재 약관·개인정보 처리방침은 **운영 문서 확정 전의 초안**이고 문의처는 미정입니다.
skn-501에서 `MenuScreen`과 `AccountScreen`의 개인정보 처리방침·이용약관·도움말/문의 진입점과 안내 시트 연결을 주석 처리했습니다.
메뉴의 비로그인·로그인·세션 복원 실패 상태, 로그인한 `내 프로필`, 회원가입 폼 모두에서 미확정 안내를 표시하지 않습니다.
회원가입의 약관·처리방침 초안 문구도 숨기며 비밀번호 조건과 기존 인증·계정 관리 기능은 유지합니다.

`src/components/ServiceInformationSheet.tsx`와 `src/content/serviceInformation.ts`의 본문·초안 상태·문의처 및 시트 구현은 삭제하지 않고 보존합니다.
현재 화면에서는 두 모듈을 가져오거나 시트를 열지 않습니다. 기존 시트 단위 테스트는 보존한 동작을 검증합니다.
운영 문서·문의처가 확정되면 본문과 `preparing`, `serviceContact`를 갱신하고 두 화면의 skn-501 주석을 해제한 뒤
메뉴 항목 타입·상태·문서 버튼·시트 연결과 관련 화면 테스트를 함께 복원합니다. 문의처 설정만으로 다시 노출되지는 않습니다.
앱에 반영하려면 변경 후 앱 빌드·배포가 필요합니다.

## AI 검색 결과와 재시도

검색 카드의 지역 안내는 검색 지역과 알려진 공고 분류 지역이 서로 다를 때 원문 확인을 권합니다.
전국·일치·미확정 분류에서는 다른 지역 경고를 만들지 않으며, 분류만으로 신청 불가를 판정하거나 결과를 제외하지 않습니다.
비로그인 화면은 서버가 반환한 이번 추천 건수와 추가 건수를 표시하고, 로그인·가입 뒤 같은 결과 토큰으로 복원합니다.

조건 해석·검색 실패는 기존 검증된 오류를 구분해 표시합니다. 서버가 지정한 재시도 대기 시간 동안 요청을 막고,
입력과 조건을 유지한 채 사용자의 재시도로만 실행합니다. 시간 초과·연결 종료로 결과를 확인하지 못한 요청은 재전송 전에
새 요청이 실행된다는 확인을 거칩니다. 검색은 성공했지만 전체 결과 조회가 실패한 경우에는 같은 결과 토큰만 다시 조회합니다.
일일·월간 사용량 정책이나 새로운 한도 API는 추가하지 않습니다.

## 현재 제공하는 기능

메뉴·상단 제목·도우미의 화면 안내는 웹과 같은 shared `design/screenTitles.ts` 이름을 사용합니다. `내 프로필`, `기업 맞춤 리포트`,
`신청 문서 작성`, `답변 입력`, `신청 문서 초안`, `중복 지원·수혜 검토`, `파트너 모집·파트너 관리`로 구분합니다.
하단의 짧은 `검색·관심함·리포트·협업·메뉴` 탭명은 유지하며 기업 화면의 로그인 안내는 `메뉴 → 내 프로필`로 연결합니다.
라우트 주소·메뉴 destination·도우미 HTTP context는 변경하지 않습니다.

- 비로그인 하단 4탭: **검색 · 협업 · 요금제 · 메뉴**, 로그인 후 하단 4탭: **검색 · 관심함 · 리포트 · 메뉴**. 검색 탭의 `AI 대화 검색 / 필터 검색`에서
  기존 검색 기능을 전환합니다. 각 검색은 처음 선택할 때 열고, 전환 중 입력·결과·스크롤 화면을
  유지합니다. 숨겨진 패널은 터치·스크린리더 탐색에서 제외하며 AI 요청은 사용자 동작으로만 실행합니다.
  AI 입력창은 iOS에서는 하단 여백, Android에서는 화면 높이를 조정해 키보드를 피합니다. 검색 탭의 실제 헤더 높이와
  검색 방식 선택줄의 측정 높이를 사용하며, 필터 검색 뒤에 숨겨진 AI 패널은 키보드 회피를 비활성화합니다.
- `/?mode=filter`는 필터 검색으로, 기존 `/chat` 주소는 `/?mode=ai`로 이동합니다.
  로그인 이동과 공고 상세의 `sourceCode + sourceProgramId` 계약은 유지합니다.
- 메뉴에서 파트너 모집·파트너 관리와 내 프로필로 진입합니다. 기업 정보는 내 프로필·리포트에서, 알림 설정은 리포트의 앱 알림 영역에서 엽니다. 리포트 탭은 본인 최신 리포트·수신 설정·기업 등록 진입을
  제공합니다. 지난 날짜별 리포트 목록과 임의의 추천 결과는 표시하지 않습니다.
- `메뉴 → 내 프로필 → 기업 프로필 관리`의 기업 기본정보 아래에서 웹과 같은 `협업·파트너 설정`을 조회합니다. 기업 등록 후에만 읽으며,
  미설정과 조회 실패를 구분하고 조회 실패에는 다시 불러오기를 제공합니다. `수정` 시트에서 참여 가능 역할·관심 분야·한 줄 소개·보유 역량을 편집하고
  기존 `/api/v1/me/company/partner-profile` GET·PUT과 shared DTO·Mapper·저장 검증을 재사용합니다. 역할은 하나 이상, 관심 분야는 최대 3개,
  소개는 200자, 역량은 30자 이내 최대 5개이며 입력 중인 마지막 역량도 저장에 포함합니다. 명시적 취소는 기존 값으로 돌아가고,
  바깥 터치·닫기·기기 뒤로가기는 변경 취소를 확인합니다. 저장 실패에는 입력을 유지하고, 저장 중에는 중복 제출과 닫기를 막습니다.
  계정·기업 변경이나 화면 이탈 시 이전 요청을 취소하며 늦은 응답을 새 계정에 반영하지 않습니다.
- 요금제는 비로그인 하단 탭(`/pricing`)과 메뉴의 서비스 안내에서 로그인 없이 읽습니다. 로그인 후에는
  메뉴 안의 `/all/pricing`에서 같은 화면을 엽니다. 신용카드 아이콘을 사용하며 무료·플러스·프리미엄 중
  비로그인은 플러스를, 로그인 회원은 조회한 현재 플랜을 먼저 보여 주는 탭 전환형입니다. 가격("9,900원 / 30일")·한도·FAQ는 웹과 같은 shared `design/pricingContent.ts`를 읽고,
  로그인했으면 현재 플랜 카드와 요약 줄을 "이용 중" 또는 "체험 중"으로 강조합니다. 이용권·체험 종료일은 서버 값과 shared `planEndsText`로 표시하며,
  체험 카드의 30일 가격에는 "30일 이용권 기준 가격"을 붙입니다. 종료일 없는 운영자 배정은 사용량 기간 종료만 안내합니다.
  최초 응답 전 직접 고른 탭과 재조회·만료 후의 선택은 유지하고, 계정이 바뀌면 초기화합니다. 조회 중·실패·재시도를 구분하고 실패를 플러스 추천으로 대신하지 않습니다.
  로그인 회원의 "내 프로필에서 이용량 보기"는 기존 프로필 화면으로 이동합니다. 무료 카드 버튼은 기존 검색으로 이동하고,
  플러스·프리미엄에는 버튼을 두지 않습니다. 출시 전 무료 체험 시작·요금제 바꾸기·결제·구독은 앱에 두지 않습니다(App Store 3.1.3).
  다른 요금제 요약과 FAQ는 펼쳐서 읽고, 마지막 검색 안내와 시작 버튼은 두지 않습니다.

리포트의 반복적인 관련도·신청 자격 안내는 카드 설명에 한 번만 표시합니다. 제공처 누락이나
원문 근거 확인 실패처럼 추천 범위를 바꾸는 경고는 추천 카드 앞에 짧게 표시하고,
내부 진단용 최근 수집 시각은 사용자 화면에 표시하지 않습니다. 새로 추가된 경고는 그대로 표시합니다.

- 필터 검색은 검색창 옆 버튼에서 한 시트를 엽니다. 지역·분야는 다중 선택이며 shared의 전체 기본 목록과 서버 추가 분류를 함께 표시합니다.
  지역·분야·출처·접수 상태 5개·K-Startup 공식 업력/대상/연령은 시트에서 임시로 선택하고 `적용`을 눌러 기존 catalog API에 한 번 제출합니다.
  닫기·바깥 터치·기기 뒤로가기는 변경을 취소하며 다시 열면 마지막으로 적용한 조건을 표시합니다. 시트의 `초기화`도 적용 전까지 결과를 바꾸지 않고,
  초기화 후 적용하면 검색어·정렬·필터를 기본값으로 돌립니다. 검색어는 키보드 검색으로 제출하며, 필터 적용으로 아직 제출하지 않은 검색어를 자동 전송하지 않습니다.
  공통 검색 검증은 기존 Core의 다중 값 길이(지역 200자·분야 300자)를 따릅니다. 정렬·페이지 이동에서도 제출한 검색어를 유지합니다. 그룹별 전체·초기화·개별 조건 해제를 지원하고 수집 기간이 없는 제공처는 상태 확인 안내를 표시합니다.
  신청문서·중복 검토의 공고 선택도 같은 시트를 사용하되 전체 접수 상태로 시작합니다. 실패를 빈 목록으로 대체하지 않고 요청 오류와 재시도를 표시합니다.
- AI·필터 검색 카드의 관심 공고 저장은 제목 옆 북마크 아이콘으로 표시하고 담은 공고는 채워진 아이콘으로 구분합니다.
  `원문 보러가기`는 카드 왼쪽에 외부 이동 아이콘과 함께 표시합니다. 충남 무역 공지는 `공식 공지 목록 보러가기`로 연결합니다.
- 공고 상세의 한눈에 보기는 접수 기간·신청 방법·문의처·지역/분야 태그·주관 기관 유형을 표시합니다. 공식 문의처 전화 연결,
  지원 내용·지원/제외 대상·우대 사항·신청 방법과 신청 사이트·구글 설문 열기, 원문 보기, 관심 공고 저장을 유지합니다.
  상세 응답의 DTO 변환은 `src/api/client.readProgramDetail`이 shared Mapper를 사용합니다.
- 원문 질문은 예시(지원 대상·신청 방법·신청 기간·문의처)를 눌러 입력만 채운 뒤 사용자가 전송합니다.
  현재 공고를 보는 동안 성공 답변과 근거 부족 답변을 질문 순서대로 쌓습니다. 취소·오류는 입력을 유지하고 늦은 응답을 폐기하며 계정·공고가 바뀌면 이력을 비웁니다.
  요청 중 시트의 닫기·바깥 터치·기기 뒤로가기는 `계속 기다리기 / 중지하고 닫기` 확인을 제공합니다.
  하단 `요청 중지`는 시트를 유지한 채 화면 대기를 중지합니다. 입력은 유지하고 늦은 답변은 반영하지 않습니다.
  계정·공고가 바뀐 뒤 이전 닫기 확인은 새 요청에 영향을 주지 않습니다. 화면 대기 중지는 서버 처리나 비용 취소를 보장하지 않습니다.
- 요금제 이용량은 `GET /api/v1/plan-usage`(로그인 시 Bearer, 로그인 전에는 토큰 없이 접속 주소의 AI 대화 검색 체험)를 shared `planUsageSchema`로
  검증해 읽습니다. AI 검색 입력창 위와 원문 질문 시트, 신청 문서 양식 분석·초안 만들기, 중복 검토 실행 근처에 남은 횟수("오늘 2회 남음")를 한 줄로 보여 주고(`FeatureUsageLine`),
  남은 양이 한도의 20%(최소 1회) 이하면 주의 색과 다시 채워지는 때를, 다 쓰면 shared 한도 안내를

## 관심함·준비 (skn-86)

관심함은 `담은 공고 / 준비 중인 작업`으로 전환합니다. 담은 공고에는 `목록 / 달력 / 진행 관리` 보기가
있으며 공고명·기관명 검색과 지역·분야·대상 다중 선택, 적용 조건 해제·초기화를 제공합니다. 같은 항목의
선택값은 OR, 서로 다른 항목은 AND로 조합하고 이미 조회한 관심 공고 안에서 거릅니다. 대상은 웹과 같은
표시 분류이며 신청 자격 판정으로 사용하지 않습니다. 목록은 마감일 오름차순이고 날짜가 없는 공고는 뒤에 둡니다.
달력은 서울 기준 오늘·월 이동·연월 선택과 날짜별 접수 시작·마감 공고를 표시합니다. 연도 직접 선택과 월 이동은 웹과 같은 2000~2100년 범위를 사용하며, 시작과 마감이 같은 날은
한 일정으로 표시합니다. 진행 관리는 관심·준비 중·지원 완료·심사 중·결과를 색상·아이콘·건수로 구분하고,
선택한 단계의 카드만 보여 줍니다. 처음에는 항목이 있는 첫 단계를 선택하며 새로고침·단계 저장 뒤에는
선택을 유지합니다. 관심은 공고 수, 나머지는 신청 문서 수이고 선정·미선정은 결과 배지로 구분합니다.
목록의 진행 배지와 진행 관리의 문서 카드에서 기존 단계 변경 시트를 바로 열 수 있습니다.
준비 중인 작업은 작업 종류와 문서·검토 상태로 필터링합니다. 신청 문서만 선택하면 신청 진행 단계도 고를 수 있으며, 필터는 계정 변경 시 초기화합니다.
준비 작업 필터와 종류·상태·신청 진행 단계 선택 시트는 내용 높이에 맞추고 마지막 선택·하단 버튼 아래의 추가 여백을 제거합니다.
기기 하단 안전영역은 유지합니다.
접수 상태·D-day·진행 단계와 문서·검토 요약을 카드로 표시합니다. 공고는 `(sourceCode, sourceProgramId)`로
연결하며, 여러 신청 문서가 있으면 목록 응답의 가장 최근 작성본을 대표 진행 단계로 사용합니다.
관심 공고 해제는 DELETE 성공 뒤 검정 안내와 7초 동안 되돌리기를 제공합니다. 되돌리기는 POST
성공 응답의 실제 저장 시각으로 복원하며 표시 목록에는 같은 마감순 정렬·조건을 다시 적용합니다.
관심 해제는 신청 문서나 중복 검토 작업을 삭제하지 않습니다.

신청 문서는 `GET /api/v1/application-preparations`의 모든 커서 페이지에서 답변 수·완성 문서 여부를
조회합니다. 중복 검토는 `GET /api/v1/combination-reviews`와 각 검토의 상세·최근 실행 요약을 읽습니다.
별도 일괄 요약 API가 없어 상세·실행 조회는 6개 검토씩 나누어 요청합니다. 현재 입력 버전의 실행만
분석 완료로 표시하며, 진행 중이면 스피너·경과 시간을 보여 주고 화면에 머무는 동안 10초마다 상태를
조회합니다. 이 조회는 유료 분석이나 문서 생성을 시작하지 않습니다. 문서 생성 작업의 실시간 상태·
경과 시간 API는 없어 해당 수치를 임의로 만들지 않으며, 답변 진행 막대는 저장된 문항 수를 사용합니다.
조회 실패는 빈 목록·관심 단계·완료 상태로 대체하지 않습니다.
관심 공고가 실제 0건이면 필터 검색으로, 신청 문서·중복 검토가 각각 0건이면 기존 새 작성 화면으로
이동하는 버튼을 제공합니다. 이동만으로 문서 생성·양식 분석·검토 분석을 요청하지 않습니다.
다른 계정의 늦은 응답·검색어·선택 시트는 새 계정 화면에 노출하지 않습니다.

담은 공고 상세의 준비 구역은 동일 API로 해당 공고의 문서·검토만 표시합니다. 진행 단계 바꾸기는
선택한 신청 문서의 `PUT /api/v1/application-preparations/{id}/progress-stage`에 저장된
`expectedProgressRevision`을 전달합니다. 저장 충돌은 오류로 표시합니다. 새 문서·신청 문서 행은
앱의 `/all/preparation` 작성·결과 화면으로 이동합니다. 외부 공식 신청 페이지는 사용자가 직접 엽니다.
검토 요청·결과 행은 앱의 `/all/reviews` 하위 화면으로, 신청문서 작성·결과는 `/all/preparation` 하위 화면으로 연결합니다.
공고 상세는 기관·지역·분야·지원 대상·사업 내용·자격 확인 안내와 공식 원문 링크를
처음부터 표시하며, 더 보기·접기 버튼을 사용하지 않습니다. 하단에는 책갈피·원문에 질문하기를
두고 Android 하단 안전 영역을 적용합니다. 질문 시트를 여는 것만으로 AI 요청을 실행하지 않습니다.
원문 질문 시트는 공용 `PartnerSheet`의 기본 배경 가림을 사용합니다. 바깥 영역·닫기 버튼·기기 뒤로가기에서
요청 중에는 중지 확인을 거치고, 대기 중인 요청이 없으면 바로 닫습니다.
원문 근거 답변을 지원하지 않는 공고는 미지원 안내와 공식 원문 확인 버튼을 바로 표시하며,
로그인이나 질문 입력을 거치지 않고 공식 페이지로 연결합니다.

## 중복 지원·수혜 검토 (skn-104)

`메뉴 → 신청 준비 → 중복 검토`에서 본인 목록에 진입하며, `/all/reviews/new`와
`/all/reviews/:id`에서 `공고 2개 선택 → 분석 확인`을 제공합니다.
기업 등록을 선행 조건으로 만들지 않습니다. 공고 선택은 기존 `CatalogScreen`의 필터와
`ProgramCard`를 재사용하며 접수 상태만 `전체`로 시작합니다. 카드 탭은 상세 조회이고 선택 버튼은 비교 대상 추가·해제입니다.
관심 공고는 처음 선택할 때 조회하며 검색 조건·선택은 화면 전환 중 유지합니다. 분석 확인 단계의 `내 상황(선택)`에서
사업별 지금 상태(모름·신청 전·신청함·선정·협약·수행 중·받음·종료), 두 사업의 관계(같은 과제·제품, 같은 비용 항목: 예·아니오·모름),
추가 설명을 고르며 모두 비워 둬도 분석할 수 있습니다. 상태와 저장된 사실 6개 사이의 변환은 shared의
`CombinationReviewParticipation`을 웹과 함께 사용하고 실제 지원금 지급 사실은 독립적으로 보존합니다. 관계(`relation`)는
불러온 값을 모든 저장 요청에 그대로 다시 보내 웹에서 고른 값을 앱 저장이 지우지 않습니다.

호출은 `화면 → useCombinationReview → shared CombinationReviewUseCase → MobileCombinationReviewRepository → Core API`이며,
모바일 Bearer 인증과 shared DTO 검증을 사용합니다. 입력 저장과 분석 POST는 사용자 확인 버튼으로만 실행합니다.
공고 선택의 다음 버튼에서 검토를 생성하고 `/all/reviews/:id?step=confirm`으로 이동합니다.
분석 확인의 이전 버튼은 바꾼 입력을 같은 ID·입력 버전으로 저장한 뒤 단계만 바꾸고, `검토 실행`은 바뀐 입력이 있으면
먼저 저장(입력 버전 확인)한 뒤 저장된 버전으로 분석 POST를 보냅니다. 저장 실패·버전 충돌 시 현재 단계와 입력을 유지하며
분석을 요청하지 않습니다. 이미 저장한 입력은 다시 저장하지 않습니다. 제목·공고·내 상황의 저장 안내와
추가 설명의 실행 시 저장 안내를 구분합니다. `step=selection|confirm|analysis`는 단계 복원을 위한 앱 주소이며,
예전 참여 상태 단계 주소 `step=participation`은 분석 확인 단계로 엽니다. 단계가 없는 기존 검토·실행 링크는 기존 결과 화면으로 진입합니다.
접수 HTTP 대기는 15초로 제한하며 서버 작업 취소를 보장하지 않습니다. 접수 전 API origin·계정 이메일별 SecureStore에
검토 ID·요청 키·입력 버전·추가 설명을 보관합니다. 저장소 확인·쓰기 실패는 새 분석을 막습니다.
전송 결과가 불명확하면 같은 내용·키로만 수동 확인하며, 명시적인 4xx 거절 또는 확인된 접수 뒤 기록을 지웁니다.
로그아웃에는 해당 계정의 보관 요청도 삭제하고 계정 전환에는 화면을 다시 생성해 이전 응답을 차단합니다.

실행 화면은 대기·분석 중인 선택 실행만 직전 GET 완료 후 3초 간격으로 조회합니다. 목록은 진행 중인 검토가 있을 때
10초 간격으로 조회합니다. 화면 이탈·앱 배경 전환·조회 실패·완료에는 조회를 중단하며 다시 진입해 저장된 상태를 확인합니다.
UNKNOWN은 새 분석을 차단하고 운영 확인을 안내합니다. 실패를 허용·근거 부족으로 표시하지 않습니다.
과거 입력 결과와 실행 당시 사업 순서를 구분합니다. 세 질문 방식(v3) 결과는 웹과 같은 순서로 결론 카드(질문별 판정 칩·판정 조합으로 정한
결론 문장·"찾지 못함 ≠ 허용" 안내·접힌 AI 요약) → 질문 카드 3장(판정 칩·설명·조건 → 가능/불가와 접힌 조건 근거·기관에 물어볼 것·
처음부터 펼친 답 근거·걸리면 생기는 일과 접힌 조치 근거, 규정 없음은 허용이 아니라는 안내) → 내 상황으로 좁히기(사업별 상태·관계 2칸,
바꾼 뒤에만 `저장하고 다시 분석`이 켜지며 저장 후 새 실행을 접수하고 그 실행을 보여 줌) → 접힌 공식 원문·판단 한계를 표시합니다.
지난 여섯 단계 방식(v2) 결과는 이전 방식 안내와 `새 방식으로 다시 분석`(진행 중·결과 확인이 필요한 실행·응답을 확인하지 못한 요청이 있으면
이유와 함께 막음)을 붙이고, 그 아래는 기존 결론 카드(판정 개수·단계 색 띠) → 먼저 확인할 것(내 상황 입력하고 다시 보기) → 접힌 단계 줄 그대로입니다.
결론 문장·판정 색 단계·질문 고르기는 shared `CombinationReviewResult`를, 근거 원문 정리(관련 줄 중심 기본 보기·앞뒤 원문 보기·
원문 그대로·다른 단계/질문 인용·신청서 서식 표시)는 shared `CombinationReviewEvidence`를 웹과 함께 사용합니다.
공식 HTTPS 공고·첨부 주소는 외부에서 열며, 보관한 원본 파일 자체의 다운로드는 현재 웹에서 제공합니다.
중복 검토 결과는 헤더의 뒤로가기를 사용하며 별도의 목록 이동 버튼과 비어 있는 하단 버튼 영역을 표시하지 않습니다.

## 협업 (skn-85)

메뉴 → 협업의 모집글은 비로그인도 조회합니다. 검색·찾는 역할·지역·내 글·마감순/최신순을
Core API 파라미터로 요청하고, 모집 상태·제안 건수는 서버 응답을 사용합니다. 모집글 상세는
연결된 공고의 `(sourceCode, sourceProgramId)`로 앱 공고 상세에 이동합니다.
기업 등록이 확인된 계속사업자는 메시지 500자 이내로 제안할 수 있습니다. ‘기업 정보 함께 보이기’는
기업 기본정보 공개 여부만 결정하고, 이메일·사업자번호는 수락 뒤에만 표시합니다. 받은/보낸 제안함,
수락·거절·철회와 응답 대기 배지는 모바일 Bearer 인증으로 기존 Core API에 연결됩니다.
제안 날짜·응답 기한은 서울 기준으로 표시합니다. 별도 푸시·읽음 상태는 제공하지 않습니다.

협업의 모집글·제안함 머리글에 있는 연필 버튼은 앱 내부 `/partner/new` 작성 화면을 엽니다.
로그인과 계속사업자 등록을 확인하고 관심 공고 선택 → 역할·조건 → 협업 소개를 한 화면에서 입력합니다.
관심 공고는 선택 시트에서만 조회하며, 접수 중이고 모집 마감일을 정할 수 있는 공고만 선택합니다.
공통 작성 UseCase가 입력을 정규화·검증한 뒤 `POST /api/v1/partners/recruitments`를 앱의 Bearer 세션으로 호출하고,
등록 성공 시 기존 `/partner/[id]` 상세로 이동합니다. 오늘부터 공고 접수 마감 전날까지 달력으로 선택하며,
공고 마감일이 미정이면 상한을 두지 않습니다. 실패 시 입력을 유지하고, 중복 요청과 이전 계정의 지연 응답을 차단합니다.
작성 중 입력은 화면에만 보관하며 화면을 닫으면 사라집니다. 입력이 있으면 취소·뒤로 가기에서
이탈 확인을 표시하고, 계속 작성을 선택하면 입력을 유지합니다. 등록 요청 중에는 결과 확인 전
이탈을 막으며 등록 성공 후에는 확인창 없이 상세 화면으로 이동합니다.

수정·모집 마감 버튼은 상세 맨 위의 공고·마감 배지 오른쪽에 두며, 공간이 부족하면 오른쪽 정렬된 다음 줄로 내려옵니다.

내 모집글 상세의 수정 버튼은 앱 내부 `/partner/edit?id={id}`를 엽니다. 기존 작성 폼에 현재 내용을
채우며 연결된 공고는 바꾸지 않습니다. 본인의 모집 중인 글만 수정할 수 있고, 공통 수정 UseCase가
입력을 정규화·검증한 뒤 `PUT /api/v1/partners/recruitments/{id}`를 앱의 Bearer 세션으로 호출합니다.
수정 성공·취소 후 같은 모집글 상세로 돌아가 최신 내용을 다시 읽습니다. 저장 실패 시 입력을 유지하며,
변경한 입력의 이탈 확인·중복 저장 방지·이전 계정의 지연 응답 차단은 작성과 같은 폼에서 처리합니다.
수정에는 웹 origin이나 별도 웹 로그인이 필요하지 않습니다.

링크 복사는 `expo-clipboard`로 모바일 브라우저에서 열 수 있는 공개 웹 모집글 상세 주소를
복사합니다. 앱 `.env.local`의 `EXPO_PUBLIC_WEB_BASE_URL`에 웹 origin을 설정해야 링크를 복사할 수
있습니다. 개발용 로컬 HTTP 주소는 휴대폰에서 접근 가능한 주소여야 합니다. 이 변수는 공개 설정이므로
토큰·비밀값을 넣지 않습니다. 값이 없으면 다른 주소를 추측하지 않고 설정 오류를 표시합니다.

## 맞춤 리포트 (skn-83)

리포트 탭은 로그인 후 `GET /api/v1/me/daily-reports/settings`, `/latest`,
`/api/v1/me/company`를 모바일 Bearer 인증으로 조회합니다. 추천 카드가 있으면 본인 저장 공고 목록도
조회해 책갈피 상태를 표시합니다. 카드의 상세 보기·공식 원문·책갈피는 기존 공고 상세와 저장 API에
연결됩니다. 원문은 제공처가 보낸 공식 HTTPS 주소만 사용하며 리포트 자체의 AI 점수는 선정 확률이 아닙니다.
저장 상태를 읽는 동안이나 조회에 실패해도 리포트와 상세·원문 동작은 유지합니다. 저장 상태가
미확인이면 책갈피 조작만 비활성화하고 오류·재확인 버튼을 표시합니다. 재확인은 저장 목록만 읽습니다.

리포트가 없을 때는 기업 지역·업종과 지원 목적의 3항목으로 조건 완성도를 계산합니다. 다음 리포트
안내는 기업 등록·수신 동의·주소 확인·SMTP·스케줄러 상태에 따라 달라집니다. 수신 설정에서 지원 목적
수정, 명시적인 정기 수신 동의, 확인 메일 요청을 할 수 있습니다. 확인 메일의 링크는 기존 웹에서
확인하며, 메일 서버 접수는 받은 편지함 도착 보장이 아닙니다. 오늘의 리포트는 그날 생성 당시 조건을
보존하므로 이후 설정 변경으로 결과가 바뀌지 않습니다.

화면 진입이나 새로고침으로 유료 AI 미리보기를 생성하지 않습니다. 생성 요청은 웹의 별도 명시적
버튼에서만 가능하며, 최신 조회는 `GENERATING`·`READY`·`FAILED`와 발송 상태를 구분합니다.
앱을 추가해도 백엔드·DB·AI 서비스를 복제하거나 새 클라우드 리소스를 생성하지 않습니다.

## 화면 기준 (skn-78 · 1단계)

[확정 시안 10장](https://govbiz-mobile-review-v2.kds20001026.chatgpt.site)을 디자인 기준으로 사용합니다.
`src/ui.tsx`의 색·글자 크기/굵기·간격·알약 버튼·카드와 `src/components/AppIcon.tsx`의 원본 SVG 경로를
공유합니다. 관심함 아이콘은 책갈피이며 `react-native-svg`는 Expo SDK 57의 호환 버전으로 고정합니다.
글꼴은 현재 기기의 기본 한글 글꼴을 사용합니다. 시안의 웹 글꼴과 실제 기기 차이는 실기기 시각 검증 대상입니다.
세그먼트는 흰색 선택 면과 회색 트랙을 사용하며 글자 확대 시 높이가 늘어납니다.
공통 버튼은 작은 크기에서도 최소 높이 48을 확보합니다. 시트·로그인 닫기, 관심 공고 책갈피, AI 전송·기록 삭제는 48×48로 조정합니다.
원문·가입 링크와 검색 방식 선택·협업 필터·정렬도 최소 높이 48을 사용합니다.
받은 제안의 상태 필터는 테두리 있는 버튼과 선택 배경으로 표시합니다. 실제 기기의 누르기·글자 확대·스크린리더 확인은 별도입니다.

라우트는 `app/`, 화면 상태는 `src/screens/`, 업무 계약은 기존 `@govbiz/shared`에 둡니다.
Root/Tab 내비게이터가 헤더·탭 안전 영역을 담당하고 `Page`는 본문·키보드 회피를 담당합니다.
탭 내부 본문에는 하단 안전 영역을 다시 더하지 않습니다. 탭 밖 화면은 `Page` 또는 고정 하단 버튼 중
한 곳에서만 시스템 하단 안전 영역을 확보하며, 본문 끝에 별도 빈 스크롤 여백을 넣지 않습니다.
본문·목록·시트의 끝 탄성 스크롤은 차단합니다. 새로고침 목록은 iOS에서 위쪽 당기기를 허용하고
본문을 내려간 뒤에는 탄성을 끕니다. Android는 끝 오버스크롤을 끄고 기존 새로고침을 유지합니다.
검색 세그먼트의 실제 높이를 키보드 오프셋에 포함합니다. API·세션·유료 호출 정책은 변경하지 않습니다.
협업·관심함 세부 화면과 준비 관련 독립 화면은 후속 단계이며, 앱에서 시안 전체가 구현된 것으로
취급하지 않습니다.

## 로컬 실행

Node.js **24.x**, pnpm **11.22.x**에서 저장소 루트에서 설치합니다.

```bash
pnpm install --frozen-lockfile
cp frontend/mobile/.env.example frontend/mobile/.env.local
pnpm dev:mobile
```

`EXPO_PUBLIC_API_BASE_URL`에는 `/api`를 제외한 API origin을 지정합니다. 공개되는 설정이므로
OpenAI 키, DB 비밀번호, Vercel 프록시 비밀값, OAuth client secret을 넣지 않습니다.

| 실행 환경 | 개발 API 예시 |
|---|---|
| iOS 시뮬레이터 | `http://localhost:8080` |
| Android 에뮬레이터 | `http://10.0.2.2:8080` |
| 같은 Wi-Fi의 실기기 | `http://192.168.0.10:8080` 등 개발 PC의 LAN 주소 |
| 운영 앱 | HTTPS 공개 API origin 또는 `/api`를 제공하는 Vercel origin |

Core API·MySQL·AI Service와 검색 데이터가 먼저 준비되어야 합니다. 시작 방법은
[인프라 README](../../infrastructure/README.md)를 따릅니다. 기기의 `localhost`는 개발 PC가 아닙니다.
방화벽 및 API listen 주소가 기기의 접근을 허용하는지도 확인합니다.
API 장애를 가짜 공고·정상 빈 결과로 대체하지 않습니다.

기본 Compose는 API 포트를 PC의 `127.0.0.1`에만 노출합니다. 실기기에서 PC LAN 주소를 쓰려면
별도의 개발용 바인딩/HTTPS 개발 주소가 필요합니다. USB로 연결한 Android 기기에서는
`adb reverse tcp:8080 tcp:8080` 후 앱 API를 `http://localhost:8080`으로 지정할 수 있습니다
(Core 호스트 포트를 바꿨다면 reverse 포트도 맞춥니다). 기본 Compose만 켜고 PC LAN 주소를
설정하는 것으로는 실기기에서 연결되지 않습니다.

설치된 Expo Go가 SDK 57을 지원하면 일반 화면을 실행할 수 있습니다. 소셜 로그인은 고정 앱 scheme이
필요하므로 Expo Go가 아닌 네이티브 개발 빌드를 사용합니다.

```bash
# Android Studio/SDK와 JDK가 설치된 환경
pnpm --filter @govbiz/mobile android
# macOS와 Xcode가 설치된 환경
pnpm --filter @govbiz/mobile ios
```

`ios/`와 `android/`는 Expo가 생성하며 Git에 넣지 않습니다. 네이티브 설정은 `app.config.ts`와
Expo config plugin으로 관리합니다. store 등록 전 bundle identifier `ai.govbiz.mobile`과 앱 아이콘,
서명·개발자 계정은 실제 프로젝트에 맞게 확정해야 합니다. 로컬 네이티브 개발에 EAS 계정·유료 빌드는 필수가 아닙니다.

## 발표용 Android APK 배포

`eas.json`의 `preview`는 EAS `preview` 환경을 사용하는 internal APK이며 개발 클라이언트를 포함하지 않습니다.
`frontend/mobile`에서 `pnpm dlx eas-cli@latest build --platform android --profile preview`로 빌드한 APK를
Firebase App Distribution 콘솔에 올려 팀원 확인 후 참석자 초대 링크·QR로 제공합니다.
Expo 프로젝트는 `@seop1026/govbiz`이며 실제 프로젝트 UUID는 환경변수에서 읽습니다.
Android 패키지는 `ai.govbiz.mobile`, 현재 버전은 `0.1.0`/`versionCode=3`이며 업데이트마다 versionCode를 올립니다.
기본 아이콘은 최초 선택한 G 모노그램 원본인 `assets/icon.png`를 사용합니다. Android adaptive icon은
G를 줄이고 투명 여백을 늘린 전용 전경 `assets/adaptive-icon.png`와 배경색 `#E7F6ED`를 합칩니다.
아이콘 변경은 새 APK 빌드·설치 후 실제 런처에서 확인하며, JavaScript 업데이트만으로 적용되지 않습니다.

먼저 [.env.preview.example](.env.preview.example)의 실제 API HTTPS origin과 Expo 프로젝트 UUID를 준비해
EAS 프로젝트의 `preview` 환경에 등록하세요. `.env.local`은 클라우드 빌드에 전달되지 않습니다.
preview 빌드는 UUID 누락·형식 오류와 잘못된 API/웹 origin을 명시적인 오류로 중단합니다.
Firebase 배포는 기존 Core·AI·DB를 사용하며 앱 푸시를 제공할 때만 FCM 설정을 추가로 준비합니다.
준비할 프로젝트 정보·환경변수·서명·설치 확인은 [Android APK 배포 안내](../../docs/mobile-app-distribution.md)를 따릅니다.
발표용 변경은 작업 브랜치에서 검증하며 실제 APK 배포·실기기 확인·병합은 각각 별도 단계입니다.

## 인증과 소셜 로그인

이메일 로그인·회원가입은 `/api/v1/auth/mobile/login`, `/signup`에서 Bearer 세션을 발급받습니다.
앱은 세션 토큰을 SecureStore에 API origin별로 저장하고 브라우저 쿠키와 섞지 않습니다.
기존 웹은 HttpOnly 쿠키와 Origin 검증을 계속 사용합니다.

소셜 로그인을 활성화하려면 서버에 기존 Google·Kakao client 설정과 함께
`ACCOUNT_MOBILE_OAUTH_REDIRECT_URIS=govbiz://oauth/complete`를 설정하고,
앱에는 `EXPO_PUBLIC_ENABLE_SOCIAL_LOGIN=true`를 지정해 다시 빌드합니다.
공급자에 등록한 callback은 기존 HTTPS `/api/v1/auth/oauth/{google|kakao}/callback`을 유지합니다.
앱은 시스템 브라우저를 열고 state·PKCE를 검증해 60초 일회용 코드를 세션으로 교환합니다.
API 응답에는 토큰이 포함되지만 앱 복귀 URL에는 포함되지 않습니다.

프로덕션은 HTTPS가 필요합니다. 공개 API 및 프록시가 Authorization을 전달하고 앱 요청을 처리하는지
확인하세요. 네이티브 네트워크 스택의 redirect·cookie 동작과 실제 OAuth 공급자 설정은 기기에서 검증해야 합니다.
앱에서 프록시의 비밀 헤더를 직접 만들지 않습니다.

## 검증과 공동 개발

```bash
pnpm --filter @govbiz/mobile typecheck
pnpm --filter @govbiz/mobile lint
pnpm --filter @govbiz/mobile test
EXPO_PUBLIC_API_BASE_URL=https://api.example.com pnpm --filter @govbiz/mobile export
```

export는 iOS·Android JavaScript/리소스 번들 생성이며 `.ipa`/`.apk` 생성이나 실제 기기 검증이 아닙니다.
테스트는 mock API로 인증 경계·복원 경합·화면 동작을 확인합니다. 유료 AI 호출이나 실제 OAuth 로그인을
실행하지 않으므로 실제 검색 품질·공급자 로그인 동작 검증과 구분합니다.

공고 응답/필터/업무 규칙을 바꾸면 `frontend/packages/shared/`를 수정하고 웹·앱 검증을 함께 실행합니다.
화면과 기기 저장소 코드는 각 앱에서 수정합니다. 서버 인증·API가 바뀌면 Core API 테스트도 실행합니다.
전체 구조와 Vercel/Docker 변경사항은 [웹·앱 공동 관리](../../docs/mobile-monorepo.md)를 참고하세요.

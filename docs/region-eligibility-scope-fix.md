# 지역 자격 범위·인용 근거 개선

기준일: 2026-09-07. [검색 오류 수정 검증](support-program-ranking-timeout-fix.md)에서 남은
서울→서초구 자격 과대 판정과 지역 근거 없는 MATCH의 후속 개선이다.

## 발견한 문제

- 회사 지역이 서울뿐인데 서초구 소재 기업 한정 공고를 지역 `MATCH`로 판단했다.
- AI 훈련 내용처럼 지역 제한을 말하지 않는 구절을 인용하고도 서울이 포함된다고 설명했다.
- 기존 서버 검사는 인용문이 원문에 존재하는지 확인하지만, 그 인용이 지역 판정을 의미적으로
  뒷받침하는지까지 판단하지 않는다. 원문 문자 일치만으로 자격 정확도가 보장되지는 않는다.

## 변경 범위

기존 모델 `gpt-5.6-luna`, 추론 `none`, 요청당 랭킹 1회, 45/50초 제한, 후보 최대 20개,
배점·정렬·부적합 제외 및 v4 HTTP 계약은 유지한다. 새로운 지역명 정규식 판정기·행정구역 DB,
규칙 기반 fallback, 자동 추가 모델 호출은 도입하지 않는다.

프롬프트와 LLM 내부 `regionAssessment` schema 설명을 다음 기준으로 보강했다.

| 확인된 회사 소재지 | 공식 API 본문의 신청 지역 | 기대 지역 판정 |
|---|---|---|
| 서울 | 서울 서초구만 | UNKNOWN: 서초구 소재 여부 확인 필요 |
| 서울 서초구 | 서울 전체 | MATCH |
| 서울 강남구 | 예외 없이 서초구만 | INCOMPATIBLE |
| 서울 | 소재지 제한 없이 전국 기업 신청 가능 | MATCH |
| 서울 | 지역 정보 없음, 전국 태그만 존재 | UNKNOWN |
| 부산 | 서울 소재 또는 기한 내 서울 이전 기업 | UNKNOWN: 이전 의사·기한 충족 미확인 |

지역 MATCH는 확인된 소재지가 공고 허용범위에 포함돼야 하며, 충돌하지 않는 것만으로는 부족하다.
태그·제목·기관 주소·행사 장소와 일반 대상/지원 내용을 지역 자격의 근거로 쓰지 않는다.
선택한 인용에는 소재지 허용·제한·지역 무관 신청을 표현하는 구절이 있어야 한다.
적용 지역이 있으면 검색 문장의 더 좁은 희망 지역으로 회사 소재지를 보충하지 않는다.

호출 흐름: **HTTP API → Service → Agent → OpenAI → Response**.
OpenAI가 기존 후보별 원문 번호를 선택하고, Agent가 원문으로 복원한 뒤 Service가 전체 후보의
인용·점수·자격 계약을 검증한다. 이번 기준 보강은 모델의 의미 판단 지침이며, 서버가 지역 관계를
독립적으로 증명하는 새 검증기나 최종 신청 자격 보증은 아니다.

## 검증 기준과 기록

- AI 전체 **571개 통과**(Windows Python 3.12.13, 22.65초, 기존 564 + 신규 7).
  일반/기업 조건 요청에 강화 지침이 전달되고, 적용 서울 조건을 서초구로 바꾸지 않으며,
  UNKNOWN 응답을 그대로 복원하는 계약과 실제 SDK schema의 지역 설명 전달을 검증했다.
  이 모의 테스트는 실제 모델의 지역 의미 정확도 증거가 아니다.
- 합성 공고 8개 × 서울/서울 서초구/부산 조건 3개로 24개 지역 판정을 평가하도록 기대값을 고정했다.
  기대값은 LLM 입력에 넣지 않는다. 최종 상위 5개만이 아니라 제외 전 전체 후보를 검사하고,
  known 판정의 인용에 실제 지역 구절이 들어 있는지도 확인한다.
- 검색 평가 도구 전체 **101개 통과**(네트워크·소켓 없는 Linux 일회용 컨테이너, 9.050초,
  실패·오류·건너뜀 0). 신규 지역 평가 20개와 실행기 14개를 포함한다. Windows의 기존 symlink
  권한 실패 2건은 Linux 전체 실행에서 통과했다. 평가기 오탐/누락, 정답 입력 혼입 방지, 실제 SDK
  요청 횟수·사용량·해시·오류 중단·키/오류 문자열 제외를 검증했다.
- 실제 API 승인은 이번 검증 최대 5회: 가상 조건 랭킹 3회 + 기존 문제 검색의 랭킹 1회/임베딩 1회.
  자동 재시도 없이 실행하며, 과거 검증 결과를 이번 개선의 결과로 재사용하지 않는다.

## 실제 평가와 후속 보완

1차 실제 합성 3요청은 모두 API/Service 검증을 통과했지만 **24판정 중 22개 일치**로 의미 평가가
불합격이었다. 서울 기업에 추가 이전 의사를 요구해 UNKNOWN으로, 부산 기업의 이전 의사 미확인을
불충족으로 취급해 INCOMPATIBLE로 판정했다. [1차 원본 기록](../evaluation/support-program-search/runs/region-scope-20260907-v1/README.md)을 보존한다.

OR로 연결된 신청 경로는 하나를 충족하면 되고, 모든 경로가 명백히 불충족일 때만 부적합이라는 지침을
보완했다. 새 전체 AI 테스트는 **572개 통과**(16.40초)이며 실제 SDK 지역 schema 설명도 검사했다.
실행기에는 2case만 넘겼을 때 정확히 2회·16판정을 기록하는 회귀를 추가했고 **15개 통과**했다.
후속을 포함한 검색 평가 도구 전체도 Linux에서 **102개 통과**(8.961초, 실패·오류·건너뜀 0)했다.

사용자가 남은 2회를 서울·부산 재검증에 사용하도록 승인해 **16판정 모두 일치**를 확인했다.
앞서 실패한 두 예외 판정과 서울→서초구 UNKNOWN, 본문 전국 허용·태그만 존재 구분을 확인했다.
[최종 재검증 기록](../evaluation/support-program-search/runs/region-scope-20260907-v2/README.md)에 실제 입력,
응답, 사용량, 프롬프트·schema·코드 해시와 이전 실패를 보존한다.

이번 유료 호출은 합계 랭킹 **5회**, 임베딩 **0회**이며 승인 한도 내에서 종료했다. 모델·추론·후보
내용은 유지했고 같은 두 case의 실제 입력 해시도 v1과 v2가 같았다. 최신 프롬프트로 서초구 명시 case를
다시 실행하거나 실제 카탈로그의 Web→Core→AI 검색을 재실행한 결과는 아니다. 합성 개발 사례는
독립 heldout이 아니며 소규모 성공만으로 일반 정확도·운영 준비 완료를 주장하지 않는다.

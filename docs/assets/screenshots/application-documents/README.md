# 신청 문서 작성 실제 사용 화면

메인 README의 **8.3 신청 문서 작성**에서 사용하는 실제 웹 화면입니다.

- 캡처일: 2026-10-12
- 화면: 로컬 React 웹 `http://127.0.0.1:5173`의 신청 문서 선택·답변·검토·생성 결과 화면
- 브라우저: 기존 테스트 계정으로 로그인한 Codex 내부 브라우저. 계정 정보가 나오지 않도록 사이드바를 접었습니다.
- 공고: 기업마당 `PBLN_000000000126762`, `[대구] 2026년 장애인기업 경영개선 지원사업 공고`
- 양식: `2026년 대구광역시 장애인기업 경영개선 지원사업 신청서.pdf`
- 데이터: 기존에 분석한 공식 PDF 양식을 재사용해 작성본 `17`을 만들고 업체명에 `GovBiz 시연기업(가상)`만 입력했습니다. 자동 기입 범위는 9/31문항, 저장·기입한 답변은 1개이며 나머지 자동 기입 대상 8개와 직접 작성 문항은 비워 두었습니다. 실제 기업의 자격·신청 정보가 아닙니다.
- 조작: 전체 검색에서 공고 선택 상태 확인 → 저장된 PDF 양식 확인 → 가상 회사명 입력·자동 저장 → 검토 → 초안 생성 요청 1회 → 생성 완료 조회 → PDF 다운로드를 같은 공고·작성본으로 진행했습니다. 양식 재분석·기관 제출·개인정보 동의 선택은 하지 않았습니다.
- 실행: 생성 작업 `7`, 답변 버전 `2`가 `2026-10-12 20:11:31` 접수, `20:11:32` 실행 시작, `20:11:38` AI 호출 시작 기록, `20:13:28` 성공으로 저장되었습니다. 시각은 서울 기준입니다. 원문 분석은 저장 결과를 재사용했으며 초안 생성에는 실제 AI 경로를 사용했습니다.
- 비용 기록: 생성 요청은 1회 접수했습니다. 현재 로컬 DB에 Core의 모델 사용량 집계 테이블이 없어 모델별 호출 수·추정 비용·실제 청구액은 확인하지 못했습니다.
- 파일: 내려받은 PDF는 2페이지·821,630바이트입니다. SHA-256은 `5ce9935ff6439eb066dbdedd4757b7ae5376b887d905ad7325a4c6be21d75f2b`입니다. 문서 바이너리는 Git에 포함하지 않았습니다.
- 검증: PDF의 canonical AcroForm 필드 값과 첫 페이지 Widget의 값이 가상 회사명과 일치하고, 해당 Widget에 비어 있지 않은 appearance stream이 있음을 확인했습니다. Poppler로 2페이지를 렌더링해 업체명 위치·한글 표시·원본 표와 두 번째 페이지의 빈 동의란을 확인했습니다. 이 1개 입력·1개 양식 확인을 다른 문항·형식의 품질 검증으로 일반화하지 않습니다.
- 편집: 기존 AI 검색 사진과 같은 **800×882 JPEG**입니다. ①~⑤는 실제 브라우저 캡처의 영역만 잘랐습니다. ⑥은 다운로드한 PDF의 첫 페이지를 폭 800px로 렌더링한 뒤 상단 여백을 제외한 y=80~962 영역을 잘라 JPEG로 저장했습니다. UI 문구 수정·응답 대체·회사명 이미지 합성은 하지 않았습니다.
- 배치: 기존 8.1과 같은 2열 표를 3행으로 확장했습니다. 단계 번호·한 줄 설명·표시 폭 320px·원본 이미지 링크를 유지합니다.
- 한계: 검토 바로가기를 사용했으며 전체 문항을 작성·검수한 실행은 아닙니다. ⑥은 실제 PDF 첫 페이지의 일부이며 두 번째 페이지는 사진에 넣지 않았습니다. 이번 시연은 로컬 웹·Core·AI·DB 경로의 완료 확인이고, 배포 웹의 문서 워커 문제 해결·기관 제출·HWP 뷰어 검증 완료를 뜻하지 않습니다.

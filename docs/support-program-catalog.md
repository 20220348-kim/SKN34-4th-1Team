# 지원사업 직접 조건 검색

## 목적과 호출 흐름

자연어 검색과 별도로, 사용자가 선택한 필터를 그대로 적용해 저장된 공고 목록을 조회합니다.
LLM 검색 장애를 숨기는 fallback이 아니라 사용자가 선택하는 별도 조회 기능입니다.

`HTTP GET → SupportProgramCatalogController → SupportProgramCatalogService → SupportProgramRepository → MyBatis Mapper → MySQL`

- 기존 `findPublishedPresent()`로 공개된 스냅샷만 한 번 읽습니다.
- AI Service, OpenAI, Qdrant, 기업마당·K-Startup 외부 API를 호출하지 않습니다.
- 공개 이후 색인 장애가 있어도 목록 조회는 가능합니다. 아직 공개되지 않은 공고는 노출하지 않습니다.
- 기존 AI 요청 제한과 별개로 동작하며, 요청마다 유료 API 비용이 발생하지 않습니다.
- K-Startup 전용 분류는 V7의 `startup_details` JSON에 보관하며 기존 공개 스냅샷과 함께 읽습니다.

## 요청

`GET /api/v1/support-programs/catalog`

| 파라미터 | 기본값 | 허용 범위·동작 |
|---|---|---|
| `keyword` | 빈 문자열 | 최대 100 UTF-16 코드 단위. 앞뒤 공백 제거 후 공고명 또는 기관명에 대소문자 구분 없는 포함 검색 |
| `region` | 빈 문자열 | 최대 50 UTF-16 코드 단위. 앞뒤 공백 제거 후 제공처 지역 태그와 정확히 일치 |
| `category` | 빈 문자열 | 최대 100 UTF-16 코드 단위. 앞뒤 공백 제거 후 제공처 분야 태그와 정확히 일치 |
| `sourceCode` | 빈 문자열 | 전체 제공처. `BIZINFO`, `KSTARTUP`, `MSIT`, `CNTRADE_NOTICE`로 제공처 제한 |
| `startupStage` | 빈 문자열 | 최대 100 UTF-16 코드 단위. K-Startup 창업 업력 분류와 정확히 일치 |
| `applicantType` | 빈 문자열 | 최대 100 UTF-16 코드 단위. K-Startup 신청 대상 분류와 정확히 일치 |
| `founderAge` | 빈 문자열 | 최대 100 UTF-16 코드 단위. K-Startup 연령 분류와 정확히 일치 |
| `status` | `OPEN` | `ALL`, `OPEN`, `UPCOMING`, `CLOSED`, `UNKNOWN` |
| `sort` | `RECENT` | `RECENT`, `DEADLINE` |
| `page` | `1` | 1부터 1,000,000까지 정수 |
| `pageSize` | `12` | 1부터 50까지 정수 |

- 문자열 길이는 trim 전 입력 기준이며 제어 문자·제로폭 문자 등 Unicode C 범주 문자를 허용하지 않습니다.
- 비어 있거나 공백뿐인 키워드·지역·분야는 해당 필터를 적용하지 않습니다.
- 키워드는 문장 해석·유의어 확장·공백별 토큰 분해를 하지 않습니다. `%`, `_`도 문자 그대로 찾습니다.
- 키워드의 공고명/기관명 조건끼리는 OR이고, 키워드·지역·분야·접수 상태 필터끼리는 AND입니다.
- 알 수 없는 지역·분야 태그는 필터를 무시하지 않고 0건을 반환합니다.
- 전용 필터가 있으면 `sourceCode=KSTARTUP`이 필수입니다. 잘못된 조합은 DB 조회 전에 400으로 거부합니다.
  공백 제거 후 각 분류를 AND로 결합하며, 데이터가 없거나 다른 분류이면 일치하지 않습니다.
  ‘3년미만’을 선택해도 ‘7년미만’으로 자동 확장하지 않습니다. 숫자 업력을 판정하는 기능이 아닙니다.
- `status=ALL`은 접수 중·예정·마감·미확인을 모두 포함합니다. 다른 값은 해당 상태만 반환합니다.
- 접수 상태는 기존 Repository에서 서울 기준 현재 날짜와 신청 기간으로 계산한 값을 사용합니다.
- 잘못된 enum, 숫자 형식·범위, 문자열 길이·문자는 DB 조회 전에 `400 REQUEST_VALIDATION_FAILED`로 거부합니다.
  응답에 입력 원문이나 내부 변환 예외를 노출하지 않습니다.

예시:

```http
GET /api/v1/support-programs/catalog?keyword=수출&region=서울&category=수출&status=OPEN&sort=DEADLINE&page=1&pageSize=12
```

## 지역 태그와 자격 판정의 구분

이 기능은 **제공처의 분류 태그**를 탐색 조건으로 사용합니다. 서울은 서울 태그에만 일치하며 경북이나 전국 태그를
자동으로 포함하지 않습니다. 전국 공고는 전국 태그를 직접 선택하거나 지역 필터를 해제해서 찾습니다.

태그에 해당 지역이 있다고 기업 소재지·업종·업력 등 신청 자격이 충족되는 것은 아닙니다. 현재 소재지를 추정하거나
원문 자격 조건을 AI로 판단하지 않으므로, 상세 안내와 공식 원문에서 최종 신청 요건을 확인해야 합니다.

## 정렬과 페이지

- `RECENT`: 제공처 정렬 시각 내림차순. 누락·빈 시각은 마지막. 동점은 `sourceCode`, 원본 `id` 오름차순.
  K-Startup API는 게시일을 제공하지 않으므로 접수 시작일을 정렬 기준으로 사용합니다.
- `DEADLINE`: 신청 종료일 오름차순. 종료일 없는 공고는 마지막. 동점은 위 최신순 정렬 사용.
- `ALL`에서 마감순을 선택하면 이미 마감된 날짜도 포함하여 날짜 오름차순으로 정렬합니다.
- 서로 다른 제공처의 같은 원본 ID는 다른 공고로 보존합니다.
- `total`은 모든 필터 적용 후 건수이고 `totalPages`는 페이지 크기로 나눈 올림 값입니다. 0건이면 0페이지입니다.
- 범위를 벗어난 `page`는 요청 값을 유지하고 `programs: []`와 실제 총건수·총페이지를 반환합니다. 마지막 페이지로
  조용히 이동하지 않습니다.

## 응답

| 필드 | 설명 |
|---|---|
| `programs` | 해당 페이지의 기존 `SupportProgramResponse` 배열 |
| `total` | 필터에 맞는 전체 건수 |
| `page` | 요청한 1부터 시작하는 페이지 번호 |
| `pageSize` | 요청한 페이지 크기 |
| `totalPages` | 필터 결과의 총페이지 수 |
| `regions` | 같은 전체 공개 스냅샷에 존재하는 지역 태그. 빈 값 제외·중복 제거·오름차순 |
| `categories` | 같은 전체 공개 스냅샷에 존재하는 분야 태그. 빈 값 제외·중복 제거·오름차순 |
| `startupStages` | 같은 전체 공개 K-Startup 스냅샷의 창업 업력 분류 |
| `applicantTypes` | 같은 전체 공개 K-Startup 스냅샷의 신청 대상 분류 |
| `founderAges` | 같은 전체 공개 K-Startup 스냅샷의 연령 분류 |

선택지는 페이지나 현재 필터 결과만으로 줄이지 않습니다. 한 번 읽은 같은 스냅샷으로 목록과 선택지를 계산하므로
요청 도중 동기화되어도 두 조회의 세대가 어긋나지 않습니다.

각 공고는 AI를 통과하지 않았으므로 `matchedReasons: []`, `recommendationScore: null`, `eligibilityReview: null`입니다.
API/DB 장애를 정상 0건 응답으로 바꾸지 않습니다.

## 프론트엔드 선택지 표시

- ViewModel은 기본 지역 18개(17개 시·도와 전국)·분야 18개(기업마당·K-Startup 중복 제외)를 API 응답 전부터 제공합니다.
  View는 각 목록 앞에 필터를 해제하는 ‘전체’ 버튼을 표시합니다.
- 기본값은 Core의 지역 정규값과 현재 제공처 분야명을 사용합니다. 서버 응답의 추가 분류는 기본 순서를
  바꾸지 않고 중복 없이 뒤에 덧붙이며, 정확일치 계약을 위해 별칭 변환은 하지 않습니다.
- 지연·실패·빈 응답에서도 기본 버튼을 제거하지 않습니다. 로딩·오류·재시도는 검색 결과 영역에만 표시하고,
  응답 도착이나 재시도로 편집 중인 조건을 덮어쓰지 않습니다. 선택은 ‘검색’을 눌렀을 때 적용합니다.
- 버튼 표시는 해당 분류의 공고가 존재한다는 보장이 아닙니다. 저장된 공고가 없으면 정상적으로 0건을 표시합니다.
  위 API의 `regions`·`categories`는 계속 실제 전체 스냅샷의 태그만 반환합니다.
- 출처 선택과 K-Startup 추가 조건은 URL로 보존합니다. K-Startup 선택 시 펼칠 수 있는 추가 조건에서
  업력·신청 대상·연령을 고르며, 출처를 바꾸면 전용 조건을 초기화합니다. 검색 버튼을 누르기 전에는 적용하지 않습니다.
- 추가 조건도 공식 기본 선택지와 서버 확장값을 합칩니다. 전용 조건을 쓰지 않는 요청은 이전 서버의 새 배열 필드
  생략을 빈 목록으로 호환합니다. 전용 조건 요청에서는 새 선택지 필드를 필수로 확인하고, 출처 필터와 응답 공고의
  출처가 다르면 실패로 처리합니다. 구버전 서버가 새 필터를 무시한 결과를 정상 검색으로 표시하지 않습니다.

## 현재 구현의 범위

현재 저장된 규모에 맞춰 공개 스냅샷을 메모리에서 필터링·정렬한 뒤 페이지를 잘라 반환합니다. 전용 분류의 저장·조회
매핑만 확장했으며 별도 검색 SQL·캐시·인덱스·의존성은 추가하지 않았습니다. 전체 공고 수·트래픽이 늘면 실측 후 DB 필터·페이지 조회와
선택지 조회를 도입할 수 있으며, 그때 MySQL 8.4 통합 테스트로 동일 계약을 검증해야 합니다.

## 검증 범위

- Service: 기본 접수 상태, 문자 그대로 검색, 지역·분야 정확한 일치, AND 결합, 전체 상태, 전체 스냅샷 선택지,
  최신·마감순, 날짜 누락, 제공처 복합 식별자, 페이지 경계, 자격/추천 필드 제거, DB 실패 전파.
- Controller: 기본값, 필터 전달, 상태/정렬 enum, 숫자·길이·제어 문자 검증, 최대 허용 경계, 기존 공고 응답 호환.
- 변경된 Core 코드의 마무리 검증은 JDK 21의 `./gradlew clean test --no-daemon`으로 실행합니다.
- 단위·통합 테스트 결과를 실제 자연어 검색·추천 품질 측정으로 표현하지 않습니다.

아래는 한국시간 2026-09-09에 승인받아 실행한 로컬 Docker 1회 동기화 결과이며, 현재 건수를 고정하는 설정이 아닙니다.
K-Startup은 기본 `RECENT_YEAR`로 실행했고, 기업마당·과기정통부는 각 API가 제공한 전체 페이지를 수집했습니다.

| 제공처 | 공개 공고 수 | 마지막 성공 시각 (한국시간) |
|---|---:|---|
| 기업마당 | 1,596 | 2026-09-09 21:19:03 |
| K-Startup | 4,143 | 2026-09-09 21:21:16 |
| 과학기술정보통신부 | 4,249 | 2026-09-09 21:24:54 |
| 합계 | 9,988 | — |

- 각 제공처의 새 수집 세대와 공개 세대 일치, `SUCCESS`, `index_ready=true`, DB 현재 노출 건수 일치를 확인했습니다.
- 현재 공고의 색인 텍스트·내용 해시·복합 ID로 Qdrant UUID를 재구성해 9,988건을 조회했습니다.
  벡터 누락과 payload의 ID·내용 해시·제공처 불일치는 모두 0건이었습니다. 이전 버전도 남는 Qdrant 전체 point 수를
  현재 공고 수로 대신 검증하지 않았습니다.
- 준비 상태 API는 `SEARCHABLE`, 전체 공고 9,988건을 반환했습니다. 다른 필터 없이 `status=ALL`은 9,988건,
  기본 `status=OPEN`은 1,781건이었습니다. 과기정통부 4,249건은 접수 기간 미제공으로 `UNKNOWN`입니다.
- K-Startup `20250909` 날짜 조건 응답에는 접수 시작일이 더 오래된 공고 325건도 포함됐습니다.
  이들의 종료일은 모두 기준일 이후였으며 원문 날짜를 보존했습니다. 이는 엄격한 접수 시작일 후처리 완료를 뜻하지 않습니다.
- 기존 서비스·데이터 볼륨은 유지하고 임시 수집 컨테이너만 종료·제거했습니다. 자동 동기화 설정은 기존 비활성 상태로 유지했습니다.
- 공고 원본·DB 덤프·벡터·API 키는 Git에 포함하지 않습니다. 다른 개발 환경에서 이 건수가 자동으로 복원되는 것은 아닙니다.
- 이 검증은 수집·색인 완전성 확인이며, AI 추천 정확도나 RAG 답변 품질을 새로 평가한 결과는 아닙니다.

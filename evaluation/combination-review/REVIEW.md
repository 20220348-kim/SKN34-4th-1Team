# 4-1 검수표: 2026 창업도약패키지

[자료·검증 안내](README.md) · [인용 원문과 위치](data/startup-jump-2026-v1/evidence.json) · [전체 사례 입력](data/startup-jump-2026-v1/cases.json)

상태: **AI 작성 초안, 사람 검수 0건, 기관 해석 미확인, LLM 실행 0회**.
표의 기대 결과는 완료된 평가 점수가 아니다. 공식 원문 인용은 원문 파일·문단 위치와 연결되어 있지만,
그 인용으로 각 기대 결과를 도출해도 되는지는 별도로 검수해야 한다.

## 우선 확인할 해석

| 확인점 | 근거 | 현재 처리 |
|---|---|---|
| 세 유형 중복 신청과 1개 협약·수행의 구분 | G/D-TYPES, CURRENT, LIST | 해당 관계 범위만 안내. 전체 자격·현재 접수 가능성은 별도 |
| 한 유형 확약 후 다른 유형 선정 절차의 실제 제외 시점 | G/D-COMMIT, CURRENT | 조항을 안내하되 기관 처리 완료·시점을 단정하지 않음(CR04) |
| 둘 이상 확약서를 제출한 경우 최초 제출 식별 | G/D-COMMIT, CURRENT | 정확한 시각·접수 자료 추가 요청(CR05) |
| 이전 연도 사업에 관한 예외와 과거 도약 사업화지원 협약 이력 | G/D-CURRENT, PAST, PAST-LISTS | 별도 이력 제외를 놓치지 않는 기대 결과 초안(CR08) |
| 특정 연도 글로벌 협업·성장촉진 프로그램만 참여한 예외 | G/D-PAST-LISTS | 명칭·연도·다른 참여 이력을 확인. 전체 허용으로 확대하지 않음(CR09) |
| 최초 확약 철회 후 다른 유형으로 전환 | G/D-COMMIT | 철회 효력·전환 허용은 미확보 자료이므로 기관 확인(CR18) |

## 사례별 기대 결과 초안

일반형 `G26`, 딥테크 `D26`는 실제 기업마당 공고 ID와 연결된다. `I26_UNRESOLVED`는 공고 ID가 없는 검토용 표식이며
현재 API에서 사용할 공식 공고·세부사업 ID가 아니다. CR01~13·17~18은 두 공고의 근거 12개를 함께 읽는 작은 고정 문맥 사례다.

| ID | 입력·질문 | 기대 결과의 핵심 | 금지할 확대 해석 |
|---|---|---|---|
| CR01 | 두 유형 모두 신청·확약·협약 전. 함께 신청하려 함 | 신청 관계는 범위 내 허용, 동시 수행은 제한 | 전체 자격 충족·두 사업 수혜 허용 |
| CR02 | 세 유형 비교. 투자연계형 별도 원문 미확보 | 세 유형 관계 안내는 인용, 투자연계형 상세는 근거 부족 | 투자연계형 현재 신청 가능·공고 부재 단정 |
| CR03 | 두 유형 선정, 확약·협약은 모두 NO | 두 사업 협약·수행 제한, 1개 선택 안내 | 확약 전인데 타 선정이 이미 취소됐다고 단정 |
| CR04 | 일반형 확약 YES, 딥테크는 선정 절차 중 | 최초 확약 사업의 협약 제한 안내. 실제 제외 처리 시점은 기관 확인 | 행정 처리 완료·양쪽 진행 보장 |
| CR05 | 두 확약서 제출, 순서 불명 | 최초 제출 사업을 특정할 사실 필요 + 두 사업 수행 제한 | 자유로운 재선택·동시 수행 허용 |
| CR06 | 두 협약 YES, 수행 전·교부 NO | 교부 전에도 협약 제한 확인, 기관 조치 문의 | 미교부이므로 제한 없음·임의 포기로 해소 |
| CR07 | 선정 YES, 확약·협약·수행 UNKNOWN | 각 사실 추가 질문 | UNKNOWN을 NO로 간주·다음 단계 자동 추론 |
| CR08 | 2025 도약 사업화지원 선정·협약 이력 | 연도 예외와 별도 과거 이력 제외를 함께 읽어 제한 초안 | 연도가 다르므로 무조건 허용·즉시 규정 충돌 판정 |
| CR09 | 과거 지원이 2019 창구 프로그램뿐 | 해당 과거 프로그램 예외 범위만 허용 초안 | 모든 연도 글로벌 협업 예외·전체 자격 충족 |
| CR10 | 3회 선정됐지만 협약·세부사업 불명 | 선정+협약 이력과 붙임 대상 추가 확인 | 선정/교부 건수만으로 제한 횟수 확정 |
| CR11 | 같은 해 지자체 사업 수행, 상대 규정 없음 | 현재 공고의 신청 예외와 상대 규정 부족 구분 | 모든 지자체 사업과 동시 수행·수혜 허용 |
| CR12 | 같은 인건비를 두 사업에서 수령 가능한지 질문 | 구체 비용·교부 규정은 근거 부족 | 제한 미검색을 허용으로 판단·반환액 확정 |
| CR13 | 일반형·투자연계형 상세 예외 비교 | 투자연계형 독자 규정 미확보 표시 | 가상 원본 ID 생성·제한 없음 단정 |
| CR14 | 테스트에서 근거 전부 제거 | INSUFFICIENT_EVIDENCE | 기억으로 근거 보충·허용 |
| CR15 | 같은 범위의 반대되는 가상 문장 2개 | CONFLICTING_EVIDENCE, 판단 보류 | 실제 공고 충돌이라고 소개·유리한 문장 선택 |
| CR16 | 원문 SHA-256 불일치 주입 | 실행 FAILED / SOURCE_INTEGRITY_ERROR, 판단 없음 | 정상 근거 부족 결과나 fallback으로 장애 숨김 |
| CR17 | 선정 NO·협약 YES라는 진술 | 의미·연도·시점 추가 확인, 사실 보정 금지 | 사용자 확인 없이 상태 변경 |
| CR18 | 먼저 낸 확약서를 철회하고 유형 전환 희망 | 확보 근거로 확정 불가, 기관 확인 | 자동 전환 허용·영구 전환 불가 단정 |

## 사람 검수 기록

아래 항목은 아직 완료하지 않았다. 검수자의 실제 확인 없이 체크하거나 “정답 확정”으로 표시하지 않는다.

- [ ] 원문 버전·인용 위치·본문과 각주·붙임의 범위를 확인했다.
- [ ] 사례의 가상 입력이 검토할 규정 조건을 충분히 특정하는지 확인했다.
- [ ] 기대 판단의 단계·범위·추가 질문과 금지할 확대 해석을 검토했다.
- [ ] CR04·CR05·CR06·CR11·CR12·CR18의 기관 확인/추가 원문 필요 항목을 구분했다.
- [ ] CR15는 인위적 충돌 사례이며 실제 공식 규정의 충돌 증거가 아님을 확인했다.
- [ ] 4-2에서 사용할 지원 대상·근거/사례 버전과 보류할 범위를 결정했다.

검수자: 미기록 / 검수 일시: 미기록 / 기관 확인 자료: 미확보.
수정이 생기면 해당 사례 ID, 이전·이후 근거 버전, 수정 이유를 함께 남긴다. 기존 검토 상태를 소급해 바꾸지 않는다.

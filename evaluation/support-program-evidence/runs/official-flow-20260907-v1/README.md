## 결론

**기업마당 공식 HTML 기반 공고별 RAG의 최소 구현·검증 범위는 완료했습니다.**
실제 모델에서 확인한 인용 ID 복사 오류를 수정했고, 수정 후 가상 질문 4개와 공식 공고 2건의 질문 6개를
확인했습니다. 답변 가능한 내용에는 원문 인용을 제공하고, HTML에 없는 서류·금액은 확인할 수 없다고
답했습니다. 다만 H01은 대상 요약에서 ‘중소·중견 제조기업’을 생략해 의미 검토에서 부분 일치로 남겼습니다.
소규모 AI-only 검토이며 모든 공고의 정확도나 운영 준비 완료를 뜻하지 않습니다.

이번 승인 한도 20회 중 **19회**를 사용했습니다. 이후 재확인은 저장된 자료만 사용하며 API 비용이 없습니다.
원문·질문·테스트·캡처·실행 안내는 Git 공유 대상입니다. API 키·인증 헤더·운영 DB 연결 정보는 포함하지 않습니다.

## 확인한 오류와 수정

추가 E12 실행은 HTTP 200 이후 계약 검증에서 실패했습니다. 당시 생성 텍스트에는 정상 답변과 함께
64자리 인용 ID의 마지막 `a`가 빠진 63자리 값이 있었습니다. `diagnosticCategory=invalid_answer_contract`,
`causeType=ModelBehaviorError`가 기록되어 있습니다.

- 기대 ID: `5a1b144a8e191821adb49a19ac84c7aabdf7133e2324815f9fbe15010eefaa9a`
- 모델 ID: `5a1b144a8e191821adb49a19ac84c7aabdf7133e2324815f9fbe15010eefaa9`
- [실패 캡처](../fixed-context-20260907-e12-v1/capture.json) · [실패 보고서](../fixed-context-20260907-e12-v1/report.json)

모델에게 긴 해시를 복사시키는 대신 현재 요청 청크의 배열 번호 `citationChunkIndexes`를 선택하게 했습니다.
Agent가 정수·범위·중복·상태 일치를 검증한 뒤 요청의 원래 ID로 복원합니다. 잘못된 번호를 가까운 값으로
보정하지 않습니다. 공개/내부 HTTP의 `citationChunkIds`는 그대로 유지하며 Core·Frontend 계약은 바꾸지 않았습니다.
새 provider·Agent 오케스트레이터·fallback·production 의존성은 추가하지 않았습니다.

흐름은 **HTTP API → Service → Agent → OpenAI의 번호 선택 → Agent의 원래 ID 복원 → Response**입니다.
번호가 유효하다는 사실만으로 답변 의미까지 맞는 것은 아니므로 의미 검토를 별도로 했습니다.

이전 E01 최초 실패는 생성 텍스트가 기록되지 않아 원인을 확정할 수 없습니다. 이번 E12 오류와 같았다고
단정하거나 과거 기록을 성공으로 바꾸지 않습니다.

[실행 안내](../../README.md)의 `verify_flow.py --run-dir ...`는 원문·fixture·청크 해시, 공고 식별자,
Core 각 요청/응답·인용, 공식 API 호출 순서·생성 출력·사용량을 검사합니다. 실패 원본을 포함한 가상
캡처는 `evaluate.py --capture ...`로 재계산할 수 있습니다. 실패 캡처의 종료 코드 1은 보존된 미완료 실행입니다.

API 요청은 본문 대신 SHA-256만 보존하므로 그 본문을 다시 해시할 수 없습니다. Core와 API 기록의 연결은
순서·생성 출력 대조이며 외부 호출의 암호학적 증명이 아닙니다. `completed`는 실행 완료이고 의미 품질 합격이 아닙니다.

- 공식 공고는 각각 청크 1개입니다. 연결과 인용은 확인했지만 여러 청크 중 검색 품질을 측정한 것은 아닙니다.
- 수정 후 가상 12문항 전체를 다시 실행한 것은 아닙니다. 이전 11개 성공 기록과 이번 E12·대표 4개를 구분합니다.
- 제출 서류가 없는 공식 HTML 두 건이므로, 실제 첨부 문서의 서류를 찾아 답하는 능력은 검증하지 않았습니다.
- 새로운 HTML 형식·복잡한 공격·모델 변동·다중 사용자 부하·운영 장애 복구는 이 표본만으로 보장하지 않습니다.
- 대상 조건을 빠짐없이 요약하는 품질은 H01 같은 누락 사례와 새 질문으로 별도 개선·전후 측정할 수 있습니다.
- 다음 기능은 6단계의 두 번째 제공처나 사용자 기능 중 하나를 선택할 수 있습니다. 첨부/PDF RAG가 필요하다면
  별도 범위로 수집 정책·안전한 파싱·근거 표시·고정 평가부터 정하고 진행합니다.

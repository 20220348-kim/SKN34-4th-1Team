# 질문 100개: Nori 후보 20개와 15개 비교

**결론: 이 자료에서는 목표 공고 포함이 양쪽 모두 98/100이었다. 15개로 줄이면서 추가로 빠진 목표
공고는 없었지만, Elasticsearch 검색시간 차이도 매우 작았다. 운영 한도는 변경하지 않았다.**

외부·유료 API, OpenAI, 임베딩, Qdrant, 운영 Core API 호출은 모두 0회다. 실제 검색은
별도 로컬 Elasticsearch의 HTTP API를 사용했다. 따라서 모든 종류의 API를 전혀 호출하지 않은
오프라인 재생 실험은 아니다. 프로젝트 API 키·`.env`·회원·기업·대화 DB는 읽지 않았다.

## 입력과 방법

- 공고: 기존 [2026-09-06 고정 스냅샷](../support-program-catalog-20260906-v1/review-final-v1/fixture-labeled.json)
  1,422건 전체. 오늘의 공고나 접수 상태를 다시 가져온 것은 아니다.
- 질문: [questions.json](questions.json)의 **서로 다른 공고 100건 × 질문 하나**. 기존 16개 목표를
  세 가지 표현으로 반복했던 48문장 진단과 별도다. 기존 48문장 목표를 제외한 뒤
  `SHA256("govbiz-100-20260913-v1:" + 복합 ID)` 순으로 첫 100건을 선택했다.
- 질문·목표 공고·원문 인용을 실제 검색 전에 고정했다. 선택된 공고에 맞춰 AI가 질문을 작성했고
  **사람 검토는 0명**이다. 기존 평가의 `relevantIds`, 미확정 라벨, dev/heldout은 수정하지 않았다.
- 목표 공고 분야: 경영 25, 기술 23, 금융 17, 수출 15, 인력 11, 창업 5, 내수 4건.
  같은 주제의 지역별 사업이 포함되어 100개의 통계적으로 독립적인 사용자 요구는 아니다.
- 해시 검증 후 전용 로컬 ES 9.5.3 + Nori 인덱스에 공고 전체를 색인했다. 검색 시 목표 ID나
  근거 인용으로 검색 범위를 좁히지 않고, **질문 텍스트만** `match` OR 질의에 넣었다.
- 운영 [Nori 인덱스 정의](../../../../backend/core-api/src/main/resources/elasticsearch/support-program-lexical-v1.json)를
  사용했다. `mixed`, BM25 `k1=1.2 / b=0.75`, 점수 내림차순 → 시각 내림차순 → ID 오름차순이다.
  동의어·필드 가중치는 추가하지 않았다.
- 각 질문을 실제 `size=15`, `size=20`으로 각각 검색했다. 첫 패스 + 반복 3회로
  **100 × 2 × 4 = 로컬 검색 요청 800회**이며, 색인·상태 확인과 별도 통합 테스트 요청은 별도다.
  질문·패스마다 두 크기의 실행 순서를 번갈아 적용했다.
- 15개 결과가 20개 결과의 앞 15개와 일치하고, 같은 검색의 반복 순위가 유지되는지 검증했다.

20 → 15 축소에 따른 **추가 목표 누락 0개**, 양쪽 모두 목표를 놓친 질문은 2개다.
반복 HTTP 중앙값 차이는 약 **0.14ms**다. 로컬 순차 실험에서 작게 관측된 차이이며,
통계적으로 유의한 속도 개선이나 운영 응답시간 개선을 입증하지 않는다.

후보 문서 문자 합계는 **25.16% 감소**했다. 이는 검색용 `text` 길이를 더한 값이지, AI 랭킹 요청
본문·모델 토큰·비용의 감소율이 아니다. 질문별 모든 후보·목표 순위·제외된 16~20위·시간 원표는
[report.json](report.json)에 보존했다.

두 질문은 **20개에서도 목표가 없었다.** 15개 축소 때문에 생긴 문제가 아니다. 다른 관련 공고가
검색되었을 가능성은 있으므로, 이 둘을 통째로 “아무 쓸모 없는 검색 결과”라고 판정하지 않는다.
실제 후보에는 다른 지역의 유사 사업도 섞였다. 이는 검색어를 OR로 넓게 찾는 어휘 검색 결과이며,
원문 표현 차이·지역 조건 처리의 영향을 다음에 진단할 수 있다. 이번 실험으로 원인을 확정하거나
동의어·필터·점수를 조정하지는 않았다.

## 해석의 한계와 다음 판단

1. **98%는 서비스 정확도나 전체 관련 공고 Recall이 아니다.** 미리 정한 목표 공고 하나가 포함되는지만
   셌다. 나머지 후보는 관련성·신청 자격을 판정하지 않았고, 무관 질문도 없다.
2. 공고를 먼저 보고 AI가 질문을 작성한 방식이라 원문 어휘가 유리할 수 있다. 해시·인용 일치 검증은
   자료 무결성 검사이지 AI 판정의 정확성 인증이 아니다. 실제 사용자 질문 분포를 대표하지 않는다.
3. Qdrant 의미 검색, RRF 결합, 회사 조건 추출, AI 점수화와 최종 추천은 실행하지 않았다.
   따라서 **AI에 보낼 후보를 15개로 바꿔도 최종 품질이 유지된다고 확정할 수 없다.**
4. 실험은 단일 스냅샷만 들어 있는 인덱스를 사용한다. 운영의 버전 허용 목록 필터·전체 가시성 집계·
   MySQL 조회·서비스 통신은 포함하지 않았다. 로컬 ES 시간은 운영 전체 검색시간이 아니다.
5. 이 결과는 어휘 후보 축소에 대한 긍정적인 추가 근거다. 현재 공통 `MAX_CANDIDATES=20`은
   ES·Qdrant 검색 깊이와 RRF 최종 한도에 모두 사용된다. 이번 테스트만으로 공통 상수를 15로
   변경하지 않는다. AI 후보 축소를 도입할 때에는 엔진별 검색 깊이와 최종 후보 한도를 구분해야 한다.

## 재검증 — 외부 API·Docker 없이

저장소 루트에서 실행한다. Python 3.11 이상이면 되고 추가 패키지는 필요 없다.

```bash
python3 -B evaluation/support-program-search/runs/candidate-budget-100-20260913-v1/compare.py \
  --verify-report evaluation/support-program-search/runs/candidate-budget-100-20260913-v1/report.json

python3 -B -m unittest discover \
  -s evaluation/support-program-search/runs/candidate-budget-100-20260913-v1 -p 'test_*.py'
```

검사는 1,422개 공고 내용 해시·카탈로그 지문·100개 질문의 선택 규칙·인용·유일성·결과 ID·15/20
접두 일치·시간 표본·지표를 확인한다. 입력과 실행 소스의 SHA256도 기록한다. 저장된 파일의 일치성을
재검증할 뿐 실제 HTTP 실행의 진위나 정답의 정확성을 인증하는 기능은 아니다.

## 실제 로컬 검색 재실행 — 유료 API 없음

기존 [격리 실험 환경](../../elasticsearch/README.md)을 이용한다. 실행마다 임의의 새 인덱스를 만들고,
출력 파일은 **존재하지 않는 새 경로**를 지정한다. 기존 결과를 덮어쓰지 않는다.

```bash
# 첫 설치에 한해 이미지 다운로드/Nori 설치가 필요할 수 있다.
docker compose --env-file /dev/null -f evaluation/support-program-search/elasticsearch/compose.yaml \
  up --build -d --wait --wait-timeout 180

python3 -B evaluation/support-program-search/runs/candidate-budget-100-20260913-v1/compare.py \
  --output /tmp/govbiz-candidate-budget-100-new.json

docker compose --env-file /dev/null -f evaluation/support-program-search/elasticsearch/compose.yaml down
```

이번 최초 측정에서는 **이미 설치된 이미지**를 `--no-build --pull never`로 실행해서 외부 다운로드도
하지 않았다. 스크립트의 소켓 감사 훅은 `127.0.0.1:19200` 이외 연결과 외부 DNS를 거부한다.
운영 애플리케이션과 다른 네트워크·임시 저장소를 쓰며 운영 컨테이너를 재시작하지 않는다.
종료하면 실험 색인은 사라지지만 질문·보고서는 남고 같은 스냅샷으로 재색인할 수 있다.

## 이번 실행의 검증 기록

- 신규 비교 테스트 **10건 통과**, 저장된 보고서 재계산 포함. 첫 실행 전에는 보고서가 없어서 해당
  테스트 1건을 건너뛰었고, 실제 캡처 후 10건 전부 다시 실행해 통과했다.
- 기존 검색 평가 테스트 **131건 중 129건 통과**, 기본 opt-in ES 통합 2건은 건너뛰었다.
  이어서 `LOCAL_ES_INTEGRATION_URL=http://127.0.0.1:19200`으로 비교 테스트 **36건 전부 통과**하여
  해당 실제 ES 통합 2건도 검증했다.
- 검토 도구 **108건 통과**, 기존 공유 실행·16질문 어휘 보고서·48문장 보고서 오프라인 재검증 통과.
- 별도 JavaScript 계산으로 입력·소스 해시, 인용 일치, 15/20 접두 관계, Hit·MRR·문자 합계를 교차 검산했다.
- 문서 링크와 `git diff --check`를 확인했다. Core API·AI Service·Frontend production 코드는
  변경하지 않았으므로 해당 전체 애플리케이션 테스트는 재실행하지 않았다.

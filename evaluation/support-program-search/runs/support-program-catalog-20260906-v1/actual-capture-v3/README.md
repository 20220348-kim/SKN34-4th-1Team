## 이번에 해결한 실제 장애

AI가 계산 가능한 총점까지 생성하면서 생기던 합산 오류는 Service가 다섯 점수만 더하도록 분리했다.
대상·지역의 의미 판단은 여전히 AI가 맡으며, `INCOMPATIBLE` 판정과 양수 점수는 함께 생성할 수 없도록 했다.
개수만 제한한 배열에서도 공고 ID 중복이 실제 발생해, 각 요청의 공고 ID를 필수 객체 키로 고정했다.
Agent는 검증된 ID별 판단을 기존 내부 목록으로 변환하고 Service는 기존 HTTP 응답을 반환한다.
지역·업종별 조건이나 fallback, 재시도, 새 외부 의존성은 추가하지 않았다.

호출 흐름은 `평가 CLI → Core SearchService → 후보 검색 → AI HTTP API → Service → Agent → OpenAI → Service 합산·검증·필터 → Response`다.
공개 HTTP 계약·v3 점수 정책·정렬·적격 임계값은 유지하며 AI Service 전체 테스트 185개가 통과했다.

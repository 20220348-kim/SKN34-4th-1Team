# 질문 300개: 후보 20개와 15개 비교

**300개 질문에서 목표 공고 포함은 양쪽 모두 295/300(98.33%)이었다. 15개로 축소하면서
추가로 누락된 목표 공고는 0개였다. 로컬 검색시간 중앙값 차이는 약 0.24ms로 작았다.**

이는 **Elasticsearch Nori 단독의 목표 공고 검색 진단**이다. 전체 서비스 정확도나 모든 관련 공고의
Recall을 의미하지 않는다. 운영 후보 한도는 20개 그대로 유지했다.

## 질문 구성과 실행 범위

- [기존 100개 질문](../candidate-budget-100-20260913-v1/questions.json)은 수정 없이 재사용하고,
  [새 공고 200개 질문](questions-added.json)을 추가했다. **100 + 200 = 전체 300개**이며,
  새 질문 300개를 따로 만든 것은 아니다. 질문·목표 ID는 모두 서로 다르다.
- 선택 기준은 기존과 같은 `SHA256("govbiz-100-20260913-v1:" + 복합 ID)` 순서의 첫 300건이다.
  기존 48문장 진단의 목표 16개 제외도 유지한다. 새 질문은 순서상 101~300번째 공고에 작성했다.
- AI가 공고 원문을 읽고 검색 전에 질문·목표·인용을 고정했다. **사람 검토는 0명**이며,
  검색 결과를 확인한 뒤 질문을 수정하거나 누락된 목표를 다른 공고로 교체하지 않았다.
- 동일한 [공개 공고 스냅샷](../support-program-catalog-20260906-v1/review-final-v1/fixture-labeled.json)
  **1,422건 전체**, 기준일 **2026-09-06**을 사용했다. 현재 운영 DB를 읽거나 공고를 새로 수집하지 않았다.
- 목표 분야: 경영 89, 기술 59, 금융 49, 수출 39, 인력 33, 창업 15, 내수 10, 기타 6건.
  같은 목적의 지역별 공고도 포함되므로 300개를 통계적으로 독립적인 사용자 요구로 해석하지 않는다.
- 각 질문을 `size=15`, `size=20`으로 실제 검색하고 첫 패스 + 반복 3회를 실행했다.
  **300 × 2 × 4 = 로컬 검색 2,400회**다. 색인·상태 확인과 별도 테스트 요청은 이 수에 포함하지 않는다.
- 두 크기의 호출 순서는 질문·패스마다 번갈아 적용했다. 모든 반복에서 순위가 동일하고,
  실제 15개 결과가 실제 20개 결과의 앞 15개와 일치하는지 검증했다.
- 기존 100개 역시 새 실행에서 전부 다시 검색했다. 후보 ID와 순서는 이전 100개 보고서와 모두 일치했다.
  과거 캡처를 재사용해 새 HTTP 검색을 실행한 것처럼 기록하지 않았다.

외부·유료 API, 임베딩, OpenAI, Qdrant, 운영 Core API 호출은 **0회**다. 로컬 Elasticsearch
HTTP API는 사용했으므로 완전한 무통신 오프라인 실행은 아니다. `.env`·API 키·회원·기업·대화 DB는
읽지 않았다. 기존 설치 이미지를 `--no-build --pull never`로 시작해 외부 다운로드도 하지 않았다.

## 한계와 판단

1. **98.33%는 AI가 원문을 보고 작성한 질문에서의 목표 공고 포함률이다.** 사람 검증 정답도,

2. 질문 300개 전체가 새 독립 heldout 세트는 아니다. 기존 100개는 이미 결과를 확인했던 자료이며,
   새 200개도 같은 카탈로그에서 같은 방식으로 작성했다. 기존 dev/heldout·라벨은 수정하지 않았다.
3. Qdrant 의미 검색, RRF 결합, 회사 조건 추출, AI 랭킹, 최종 추천은 **실행하지 않았다**.
   최종 AI 후보를 15개로 줄여도 품질이 같다고 확정할 수 없다.
4. 로컬 Nori의 분석기·BM25·정렬은 기존 100개 실험과 동일하다. 운영 버전 허용 목록 필터·가시성 집계,
   MySQL 조회와 서비스 통신은 제외했다. 전체 채팅 지연이나 동시 부하 측정이 아니다.
5. 다음 판단은 여전히 엔진별 검색 깊이와 RRF 최종 한도를 구분해야 한다. 이번 결과만으로 ES·Qdrant·

## 파일과 재현

- [compare.py](compare.py): 기존 100개 평가의 검증·집계 함수를 재사용하는 300개 실행기.
- [questions-added.json](questions-added.json): Q101~Q300의 추가 200개 입력. 기존 질문 파일 SHA256과

- [report.json](report.json): 300개 전체 질문·인용·목표 순위·15/20 후보 ID·시간 원표 및 세 집단 지표.
  원문 카탈로그는 중복 복사하지 않고 기존 공유 fixture를 참조한다.
- [test_compare.py](test_compare.py): 기존 100개 보존, 확장 입력 위변조 거부, 집단별 집계, 보고서 재검증.

저장소 루트에서 **오프라인 재검증**한다. Python 3.11 이상이면 추가 패키지·Docker·API 키가 필요 없다.

```bash
python3 -B evaluation/support-program-search/runs/candidate-budget-300-20260913-v1/compare.py \
  --verify-report evaluation/support-program-search/runs/candidate-budget-300-20260913-v1/report.json

python3 -B -m unittest discover \
  -s evaluation/support-program-search/runs/candidate-budget-300-20260913-v1 -p 'test_*.py'
```

**실제 로컬 검색 재실행**은 [기존 격리 환경](../../elasticsearch/README.md)을 사용한다. 아래 시작 명령은
이미지가 설치된 환경 기준이다. 이미지가 없다면 위 환경 문서의 최초 설치 절차가 필요하다.
기존 보고서를 덮어쓰지 않고 새 출력 경로를 지정한다.

```bash
docker compose --env-file /dev/null -f evaluation/support-program-search/elasticsearch/compose.yaml \
  up --no-build --pull never -d --wait --wait-timeout 180

python3 -B evaluation/support-program-search/runs/candidate-budget-300-20260913-v1/compare.py \
  --output /tmp/govbiz-candidate-budget-300-new.json

docker compose --env-file /dev/null -f evaluation/support-program-search/elasticsearch/compose.yaml down
```

호출 흐름은 `기존 100개 + 새 200개 검증 → 고정 스냅샷 별도 색인 → Nori 15/20 검색 → 전체·집단별 집계`다.
외부 연결·DNS는 기존 소켓 감사 훅으로 차단하고 `127.0.0.1:19200`만 허용한다. 정리 대상은 실험용
컨테이너·네트워크·임시 색인뿐이며 운영 컨테이너와 Git의 공고·질문·결과는 보존한다.

# v5 실제 후보의 지원 목적·모델 비교

실행일: 2026-09-07~08(서울). 고정 검색 기준일은 **2026-09-07**이다.
소규모 개발 진단이며 사람이 검증한 정답, 전체 검색 정확도, Recall/MRR 또는 통계적 우월성을 뜻하지 않는다.

## 채택한 변경

랭킹에 **지원 활동과 필수 지원 형태를 함께 확인하는 프롬프트 + `gpt-5.6-sol` / `low`**를 채택한다.
지원금 요청에서는 직접 비용 지원 근거를 요구하고, 컨설팅이나 폭넓은 지원 요청은 구분한다.
공고 ID·업종 이름을 production 코드의 블랙리스트로 만들거나 결과 개수를 강제로 채우지 않는다.

같은 지침을 Luna에 추가하거나 Luna의 추론만 높인 설정은 지역 충돌 오추천·양성 누락이 남아 채택하지 않았다.
Sol은 아래 제한된 비교에서 최종 오추천이 줄었지만, 여전히 자격 해석의 이견과 누락이 있다.
신청 자격을 확정하는 기능으로 소개하지 않는다.

| 고정 후보 질문 | 채택 설정의 실제 반환 |
|---|---|
| 서울 SW 사업화 지원금 | 모두의 창업 1개, 반복 실행도 같은 공고 |
| 소프트웨어 제품 사업화 비용 지원 | 모두의 창업 1개 |
| 서울 SW 사업화 컨설팅 | 대구 클러스터·모두의 창업·서울 기후테크 3개, 자격 확인 필요 포함 |
| 영화 후반작업비 지원 | 한국영화 첨단제작 1개 |
| 사업화 지원(형태 미지정) | 모두의 창업·대구 클러스터 2개; 이 질문은 미라벨이라 숫자 품질 평가 제외 |

지침과 모델을 동시에 바꾼 효과를 프롬프트만의 효과로 주장하지 않는다.
동일 strict 프롬프트의 Luna/low와 Sol/low 비교에서는 모델만 다르다.
단계별 독립 AI 대조는 [Luna none](none-review.md), [Luna low](low-review.md),
[Sol low](sol-review.md)에 성공·실패·누락·지연을 모두 남겼다.

## 고정 입력과 사전 검토

- 실제 Core의 읽기 전용 MySQL 조회·접수 필터·의미/키워드 후보 결합으로 20개를 내보냈다.
  전체 현재 공고 1,506개, 해당 날짜 접수 중 1,427개였다. 동기화·색인·Flyway는 실행하지 않았다.
- [내보내기 설정](export/metadata.json), [검색 추적](export/trace.json),
  [실행 코드](export/FixedRankingRequestExport.java)를 보존했다. 이 단계만 질의 임베딩 1회를 사용했다.
- [request.json](request.json)은 내보낸 원본과 동일하다. SHA-256:
  `f5e4aa61e8209bdf7264842adc5cb2cb85ed866f1c8b99ed6c8d0c1cae171949`.
- 모든 비교에서 후보·순서·원문·기준일을 고정하고 질문/확정 업종/목적만 미리 정한 사례대로 바꿨다.
  컨설팅·영화 질문도 **사업화 지원금 검색의 후보 풀**을 사용했다. 각 질문의 실제 후보 검색이나 전체 Recall 비교가 아니다.
- [ai-review.json](ai-review.json)은 비교 응답을 열기 전에 작성한 20공고 × 3질문 = 60쌍의 **AI 초안**이다.
  이전 사례의 4공고 검토 경험과 사람 검토 없음도 명시했다. 결과에 유리하도록 라벨을 수정하지 않았다.
  표현 변형에는 FUNDS 정책을 준용하며, 불확실 라벨은 정답/오답으로 강제 변환하지 않았다.

## 실행 기록

| 폴더 | 모델·추론 | 랭킹 호출 | 내용 |
|---|---|---:|---|
| `none-comparison/` | Luna / none | 13 | 기존·strict 지침의 5질문 비교 + 반복 3회 |
| `luna-low/` | Luna / low | 6 | strict 지침 5질문 + 지원금 반복 1회 |
| `sol-low/` | Sol / low | 6 | 동일 strict 지침 5질문 + 지원금 반복 1회 |

각 폴더의 `manifest.json`은 실행 설정·계획·완료 상태, `requests.json`은 요청,
`capture.json`은 20개 전체 판정과 최종 추천, `usage.json`은 실제 요청 해시·응답 상태·토큰 수다.
**25회 랭킹 모두 HTTP 200/completed**였지만 정상 HTTP가 의미 정확도를 보장하지는 않는다.
공식 `api.openai.com/v1/responses`만 허용하고 자동 재시도 0·Agent 한 턴·출력 10,000토큰·
모델 45초/Agent 50초로 제한했다. 키·인증 헤더·DB 비밀번호는 결과에 저장하지 않았다.

Sol 랭킹 구간은 31.119~43.430초, 중앙값 40.954초였다. Luna low 중앙값 30.430초보다 느리다.
이는 전체 검색/브라우저 지연이나 운영 p95가 아니며 시간 상한 근처의 실행이 있어 긴 입력에서 추가 검증이 필요하다.
초기 실행 도구 두 시도는 Docker 구버전 설치본을 발견해 **API 호출 전에 중단**했다.
그 뒤 `PYTHONPATH=/app`·v5 계약 검사를 통과한 실행만 기록했다. Docker 로컬 패키지 캐시 문제도 수정했다.
오프라인 대역 실행(13+6+6회)은 모델 호출이 아니며 위 유료 횟수에 포함하지 않는다.

## 재현과 공유

과거 파일을 덮어쓰지 않는다. 이 자료를 별도의 새 작업 디렉터리로 복사하고 AI Service 런타임과
공식 API 키를 준비한다. 키를 이 폴더에 저장하지 않는다.

- `run.py`: Luna/none 전후 13회. `run-low.py`: Luna/low strict 6회.
- `run-sol.py`: Sol/low strict 6회. 실행 프로세스의 `OPENAI_MODEL=gpt-5.6-sol`을 요구한다.
- 기본 실행은 계획만 출력한다. `--execute --offline`은 대역 검증, `--execute`만 실제 과금 실행이다.
- 각 도구는 새로운 `output/`을 요구한다. 이미 있으면 중단하며 암묵적으로 재실행하지 않는다.
- Docker 임시 경로에서는 `PYTHONPATH=/app`을 명시한다. 로컬은
  `PYTHONPATH=<프로젝트>/backend/ai-service`와 해당 가상환경 Python을 사용한다.
- `run-final-search.py --output <새 디렉터리> --execute`는 localhost 공개 검색 1회를 별도 기록한다.
  최대 임베딩 1회·랭킹 1회를 사용한다. 이 최종 확인은 고정 후보 비교가 아닌 현재 날짜의 실제 검색이다.

이 스크립트는 당시 실험 재현 자료이며 새로운 production 계층이 아니다.
과거 v3/v4 평가 점수를 현재 v5 성능처럼 재사용하지 않는다.

## 남는 한계

- 회사 소재지와 대표자 개인의 지역 요건을 혼동해 대구 여성창업 공고를 누락하는 이견이 남았다.
- 같은 지원금 질문의 모두의 창업 지역 판정이 UNKNOWN→MATCH로 바뀌었다. 최종 공고는 같아도 세부 판정은 고정되지 않는다.
- 외식업 컨설팅은 Sol에서도 의미 점수가 높고 자격 부적합으로만 제외됐다. 의미 관련성이 완전히 해결된 것은 아니다.
- 첨부 PDF/HWP와 전체 카탈로그 정답은 검토하지 않았다. 후보 밖 관련 공고는 이 실험으로 찾을 수 없다.
- 실패한 설정과 불확실 라벨을 숨기지 않으며 정확도 100%·포괄적 품질 합격으로 소개하지 않는다.

## 실제 서비스 반영 확인

2026-09-08 서울 기준, 기존 DB·Core·Web·Qdrant는 유지하고 AI 컨테이너만 재빌드·교체했다.
warm cache에서도 애플리케이션 wheel을 다시 빌드했으며 로컬 소스·이미지 소스·설치본의
Python 35개 해시가 모두 일치했다. `python -I -B`로 설치본 v5 import도 확인했다.
랭킹만 Sol/low이며 대화·원문 답변은 Luna 설정을 유지한다.

[최종 공개 검색](final-search/capture.json)은 **HTTP 200 / 50.741초 / 모두의 창업 1개**였다.
안산 한정·대구 지원금 불명·영화 촬영/후반작업 공고는 반환되지 않았고, 대상 자격은 UNKNOWN,
전체 `REVIEW_REQUIRED`를 유지했다. 표시된 100점은 검색 관련도이지 정확도 100%가 아니다.
이 실행은 9월 8일의 접수 상태를 사용하므로 9월 7일 고정 후보 비교에 섞지 않는다.

검색 준비 상태는 `SEARCHABLE`, 공고 1,506건, 색인 준비 완료로 유지됐다. 최종 검색은
임베딩 1회·랭킹 1회 성공 로그를 확인했고 재시도하지 않았다. 최초 대표 질문 11회까지 포함한
이번 작업의 OpenAI 호출 합계는 **39회**다. 계정 청구서와 동일한 집계라는 뜻은 아니다.
[배포·사용량 검증 기록](deployment-verification.json)에 집계 근거와 소스 해시를 보존했다.

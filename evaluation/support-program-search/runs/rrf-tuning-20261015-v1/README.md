# 고정16질의 RRF 후보풀·가중치·동점 비교

**사전 선택 규칙의 최고 설정은 pool100·BM25:semantic=3:1이지만, 내부 LOPO에서는 세 지표가
모두 하락했다. 제품 변경으로는 pool20·가중치1:1을 유지하고 BM25 동점 우선만 채택한다.**
이는 관측된 질의별 회귀를 피하기 위한 **결과 확인 후의 보수적 구현 결정**이다. 사전 선택 결과를
바꿔 쓰거나 새로운 선택 규칙을 검증한 결과가 아니다. 운영 배포는 수행하지 않았다.

## 비교 기준과 결과

고정 공고1,422건·기존16질의·기준일2026-09-06을 사용했다. 기존748판정을 전부 보존하고,
새 최종 후보80쌍을 두 AI 검토자가 각자 전부 판정했다. 두 결정이 일치하면 채택하고 불일치는
unclear로 남겼다. 신규 결과는 relevant1·irrelevant72·unclear7이며, 불일치는2쌍이다.
합계828쌍은 relevant47·irrelevant756·unclear25다. 사람 검토는0명이다.

아래는 **확정 관련 문서만 기준으로 한 기술적 점수**이며, 원래 양성12질의의 macro 평균이다.
남은4질의는 확정 관련 문서가 없어 Recall/MRR 분모에서 제외하고 아래 표에 별도 보존했다.
모든 방법이 이4질의에도 후보20개를 반환하므로, 동점 변경이 무결과 감지를 개선한 것은 아니다.

원래 수치도 metrics.json의 `originalReportedAggregateOnOriginalLabels`에 재계산해 보존했다.

채택 설정의 기존 대비 평균 변화는 **+0.027778 / +0.010417 / +0.006944**다. 같은 unclear
할당을 양쪽에 적용한 paired 변화 범위는 각각 **[+0.011905,+0.027778]**,

Q08의 관련 문서20위 진입으로 설명된다.

채택 설정 자체의 점수 범위는 R@20 [0.565575,0.755787], R@5 [0.333631,0.476389],
MRR@5 [0.722222,0.722222]다. 이 범위는 **미확정 판정의 가능한 배정에 대한 극값**이며
통계적 신뢰구간이나 새로운 질의에서의 성능 보증이 아니다. 각 지표의 극값을 이루는 배정은
서로 다를 수 있다. pooled relevance는 전체 공고의 완전한 관련성 판정도 아니다.

## 선택 규칙과 회귀

결과 확인 전 후보는24개로 고정했다: 각 검색의 pool20/50/100 × BM25 가중치1/1.5/2/3
× semantic/BM25 동점 우선. semantic 가중치1, RRF offset60, 최종 반환20을 고정했다.
점수는 `1/(60+semanticRank) + bm25Weight/(60+bm25Rank)`이며, 한쪽 목록에 없는 항은0이다.
동점은 지정한 검색의 순위, 마지막으로 복합 문서ID 오름차순으로 푼다.

선택은 기존 RRF 대비 훈련 질의 평균 R@5·MRR@5 비하락을 먼저 요구한 뒤 R@20 → MRR@5
→ R@5를 최대화한다. 지표 동률은 작은 pool → 작은 BM25 가중치 → 기존 semantic 동점 순이며,
완전히 같으면 frozen baseline을 유지한다. 기존 baseline은 항상 선택 가능하다.

양성12질의 중 하나씩 제외하고 나머지11개로 위 규칙을 적용한 LOPO에서 pool100·3:1이9회,
pool20·2:1이2회, pool20·1:1·BM25 동점이1회 선택됐다. held-out 평균은 기존 대비
R@20 **-0.009722**, R@5 **-0.010417**, MRR@5 **-0.020833**이었다. MRR의 paired 변화 범위도
[-0.020833,-0.020833]이다. 질의들은 이미 본 자료이며 후보군 자체도 이 자료에서 동기를 얻었으므로
이 LOPO조차 독립 홀드아웃으로 표현하지 않는다. 채택한 동점 변경만 별도로 다시 선택·검증해
성공한 LOPO 결과를 만들지 않았다.

사전 선택100/3은 Q01 R@20 -0.125, Q06 R@5 -0.25·MRR@5 -0.25, Q12 R@20 -0.20의
회귀가 있다. 전체 R@5의 paired 변화 범위도[-0.004861,+0.020833]으로 하락 가능성을 포함한다.
따라서 전체 평균 최고값을 제품 기본값으로 곧바로 올리지 않았다. `deploymentDecision`은
사전 선정(`selectedByPredeclaredRule`)과 사후 채택(`adoptedConfig`) 및 그 한계를 따로 보존한다.

후보풀을 키우는 것만으로 개선되지는 않았다. 가중치1:1일 때 pool20/50/100의 R@20은 각각
0.720139 / 0.674306 / 0.588889였다. 추가 후보의 실제 관련성·교집합 구성 변화가 있으므로
"후보를 많이 찾으면 항상 더 좋다"는 결론을 내리지 않는다.

## Capture와 비용

새 capture 안에서 semantic·BM25의 top20은 실제 pool20/50/100 호출 사이에 모두 동일했다.
과거 frozen 대비 BM25는 모든 질의에서 동일했고 semantic은9질의의 순서가 바뀌었다.
전체320개 top20 slot 중 집합 교집합은317개였다. 그러나 확장 판정으로 계산한 기존 RRF와
새 capture의 pool20·1:1·semantic 동점 baseline은 모든 질의의 known 점수·paired 범위가
같았다. `captureDrift`에 실제 순서·교체 문서를 남겼다.

승인 범위에서 `text-embedding-3-small`(1536차원)로16질의를 단일 배치 임베딩했고,
기록된 입력 사용량은594 tokens다. 기록 단가$0.02/백만 입력 tokens로 계산하면$0.00001188이며,
이는 청구서 확인액이 아니다. 승인 상한은$0.01이었다. 이후 로컬 ES/Qdrant 조회·기록 재계산·AI
참조판정에서는 추가 프로젝트 유료 API를 호출하지 않았다. 최종 LLM 추천/RAG 답변 품질·운영
지연·실제 사용자 분포·배포는 이 실험의 검증 범위가 아니다.

## 보존 파일과 무료 재계산

- [inputs.json](inputs.json):16질문, frozen 및20/50/100 실제 순위, capture metadata,
  입력 출처·해시, 사전 선정과 사후 구현 결정. 임베딩 벡터·환경변수·API 키는 없다.
- [labels.json](labels.json): 기존748레코드 전부, 신규80쌍 두 검토자의 결정·이유·인용,
  판정 정책, 근거로 쓴 원문41개의 추출 텍스트·원본 URL·캡처 SHA-256.
- [metrics.json](metrics.json): 전체24설정·3대조군·16질의별 지표/범위/관련문서 순위 변화,
  12 LOPO fold, capture drift. 전체 순위는 inputs.json에서 결정적으로 재구성한다.
- [replay.py](replay.py): Python 표준 라이브러리로만 재계산하고 저장 지표를 대조한다.

저장소 루트에서 실행한다(Python3.11이상, 추가 패키지·DB·Docker·네트워크 불필요).

```bash
python -B evaluation/support-program-search/runs/rrf-tuning-20261015-v1/replay.py
```

새 파일로 출력할 때는 `--output 새경로.json`을 사용한다. 기존 파일 덮어쓰기는 거부한다.
입력 JSON의 canonical SHA-256과 replay.py의 LF 정규화 소스 SHA-256을 확인하며, 수치만
`math.isclose(rel_tol=1e-12, abs_tol=1e-12)`로 비교한다. ID·순서·건수·문자열·해시는 정확히 비교한다.
새80판정의 완전성·인용·2인합의, 기존 원문 인용도 재확인한다. 이 검증은 기록 일관성을 확인하며
AI 라벨의 정답성이나 실제 원격 실행의 진위를 인증하지 않는다.

원래 공고 요약은 기존 [public fixture](../support-program-catalog-20260906-v1/fixture-unlabeled.json)를
참조하고 canonical 해시로 확인한다. 기존 합의 CSV의 경로·해시와 source-supported 판정의 인용·
원문도 보존한다. 작업용 work/ 폴더가 없어도 이 디렉터리와 기존 저장소 fixture만으로 재계산한다.

로컬에서 전체 설정·질의·LOPO가 작업용 원본 audit와 일치함을 확인했고 재계산 검증을 통과했다.
이 재계산은 제품 단위·통합 테스트나 CI 통과를 대신하지 않는다. 새 기록의 `replay.py`는 현재 CI에
자동 연결하지 않았으며, 이 평가 자료를 변경할 때 위 무료 명령을 수동 실행해 기록의 일관성을 확인한다.
Core 변경은 기존 GovBiz CI의 Core 전체 빌드·테스트 대상이다. 이번 로컬 작업에서는 facade·검색 Service의
선택 테스트 45개를 통과했으며, 원격 CI 실행과 운영 배포는 수행하지 않았다.
